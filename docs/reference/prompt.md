# Prompt 编写与审计

Agent 日常操作需要本地工作台服务在线；命令与 API 统一说明见[直接操作入口](agent-interfaces.md)。

当前支持 Anima Basic 和 Qwen-Image-2.1，每页可切换模型与画幅，分别保留模型专用 Prompt。
Anima 使用分类词条、逐词权重与继承、机位、人数及负向编辑器；本页词条不保存 ID，只有共享设定词条保留稳定 ID。Qwen 使用自由文本。
首次 Anima → Qwen 复制完整有效正向 Prompt，此后独立编辑，可明确重新带入。
两种输入和页面 LoRA 的持久契约见[模型适配器](../dev/model-adapters.md)。
下文整段 override、图片编号与自由文本编译规则描述 Qwen 的 `settings` 模式；
`standalone` 模式直接使用本页全文及附图，不重复追加设定或全局 Prompt。

## 编辑界面

剧情页 Prompt 总览列出项目全部剧情页，每页约 375px 窄列横向滚动；进入时定位当前页，导航树点击
只定位对应列。每页按模型展示词条编辑器或本页文本框。「保存全部修改」只保存有改动的页面；勾选页面后「保存并生成」
先保存各目标页草稿，再逐页排队，每页一张或三张。每页使用自己的内容与依赖指纹，失败页保留草稿；
外部更新不会覆盖未保存草稿，冲突需重新读取和判断。

Qwen 设定页编辑角色／场景的 `prompt_name`，每个子设定一个自适应多行文本框和参考图区。
Anima 设定页在基础／子设定 Prompt 内编辑 LoRA；页面引用自动继承，并可覆盖权重、停用或恢复继承。项目 LoRA 列表默认收起。
参考图管理（多选、排序、替换、移除）规则见 [Qwen 接入](../dev/qwen-image.md)。

剧情页保留紧凑角色标签行与场景标签行，“＋”搜索选择、标签内切换子设定、叉号移除；角色多选、
场景单选。展开标签后显示该引用的文字文本框与参考图：文字默认生效当前子设定文本，编辑即成为
本页 override，出现 override 时提供简洁状态和恢复继承动作；参考图点击切换启用。本页 Prompt 是
一个多行框。底部按实际输入顺序汇总全部启用图片：继承图片只读，本页附图可右键替换／移除、拖拽
排序，添加时可填用途说明。

生成详情按 sections 来源分段展示最终文本、参考图顺序和参数证据。

单页可选运行最终 Prompt 优化：保存本页修改后点击「优化」，工作台把当前编译后的正向文本交给本机 ComfyUI 的 Qwen-Image-2.1 PE-T2I INT8 `TextGenerate` 节点，使用官方 t2i 系统提示词。参考图文件不发送给优化器；生成时仍按原顺序传给出图模型。优化正文单独保存在 `pages/<page_id>.rewrite.json`；使用时，工作台按实际传图顺序在正文前无条件拼接 `<imageN>` 与每张图的用途说明，不要求 PE 保留这些标签。工作台展示的优化文本是最终拼接结果，只读且默认收起；原文在其下方并默认收起。优化文本上方的开关默认使用原文，状态紧邻开关。改动源文本、画幅或参考图后，旧结果显示为过期，仍允许选择它出图，状态仅作提示。已有 DSH 结果也显示为过期，重新运行即可替换。优化器返回的 `wh_ratio` 仅供查看，生成仍使用本页画幅。

## 数据契约

Anima 的共享词条与本页词条分开管理：

- 角色／场景基础和子设定新增词保留服务端生成的稳定 ID。改正文、分类或排序不改变身份。
- 子设定 `identity_overrides` 使用 `identity:<token-id>`；页面 `inheritance` 先按角色／场景来源分组，再使用 `identity:<token-id>` 或 `variant:<token-id>` 定位。
- 覆盖字段仅有 `enabled` 和 `weight`。字段缺省才跟随上游；显式值即使与上游相同也保留。恢复继承删除该字段，不再使用 `identity_disabled`。
- 上游关闭的词仍可在下游重新开启；共享词被删除后，旧覆盖显示失效，可保留原样或清理，不能按相似文字重新绑定。
- 本页词条按分类数组保存正文、绑定、权重和开关，无持久 ID；网页的临时行标识只用于拖动和撤销。

以下示例为 Qwen 模型内的文档；实际文件用 `models` 容器保存各模型输入，Agent 按范围读写，不回传整个容器。

角色／场景 `*.prompt.json`：

```json
{
  "prompt_name": "希格莉德",
  "variants": {
    "uniform": { "text": "该造型的完整自由文本描述", "reference_images": [] }
  }
}
```

- `prompt_name` 必填，创建时复制显示名称，之后独立修改、不随显示名同步；中文可用，无重名防护。
  编译输出的名称行使用 `prompt_name`，页面动作需按实际名称编写，名称调整后检查关联页面。
- 每个子设定自包含一段完整描述和有序参考图；没有 identity 层、LoRA 或子设定间继承。
  variants 的 id 集合与 visual.variants 一致。参考图条目为 `{id, file, title}`，不含 purpose。

页面 `*.prompt.json`（剧情页与设定视觉页共用同一契约）：

```json
{
  "text": "本页画面描述",
  "scene_id": "cafe",
  "scene_variant_id": "evening",
  "text_overrides": { "character:hildegard:uniform": "本页覆盖的完整描述" },
  "reference_overrides": { "character:hildegard:uniform": ["ref-<uuid>"] },
  "reference_images": [{ "id": "ref-<uuid>", "file": "reference-<uuid>.png", "title": "示意图", "purpose": "画风参考" }]
}
```

- `text` 必填字符串（可空串）；`scene_id` 与 `scene_variant_id` 成对可选，场景单选。
- 角色引用与排序沿用页面 content 的 `characters`，不在 prompt 中重复存储；画外对白 speaker
  不进入画面角色。
- `text_overrides`：key 为 `character:<id>:<variant>` 或 `scene:<id>:<variant>`。key 不存在就读取
  当前子设定文本；key 存在就使用该字符串，包括显式空串。恢复继承就是删除 key。override 不随
  上游更新，不做逐词对齐；Prompt 名称和图片说明始终来自当前引用，override 只覆盖描述文字。
- 切换子设定或移除引用时删除对应的 `text_overrides`／`reference_overrides` key；保存时 key 必须
  匹配当前引用，残留 key 被拒绝。
- `reference_overrides`：缺省跟随设定首张图，空数组停用，显式 ID 列表固定选择与顺序。
- 页面级 `reference_images` 是本页独立附图，`purpose` 可选；未填用途仍传图，只是不生成说明行。
  工作台在参考图旁直接编辑用途，与页面草稿一起保存；当前页“生成详情”按实际传图顺序展示图片与用途。
  Agent 通过页面 Prompt 的 `read/save` 修改对应条目的 `purpose`，沿用目标和依赖指纹，不另设说明文件。
- 文字 override 与图片选择相互独立：改文字不改变图片选择。

全局基础 Prompt 是 render profile 的 `prompt.text`，默认为空。项目生成设置可通过 override 的 `prompt.text` target
整段替换；用户可修改、补充画风或清空，清空时编译直接省略。不再有独立 Prompt policy 文件、
prefix/suffix、分类、权重、负向或策略选择。

## 确定性编译

同一个编译入口供编辑上下文、生成详情和任务冻结使用，不在点击生成时调用 LLM。段落间空行分隔：

1. 全局 `prompt.text`（空则省略，只输出一次）。
2. 逐角色段（按页面 content 引用顺序）：`<prompt_name>：`、有图时一行图片说明
   `<imageN>：<prompt_name>的身份与服装参考。`、生效文字（override 或子设定文本）。
3. 场景段（同上，图片说明为“的环境外观参考。”）。
4. 填了 `purpose` 的本页附图每个一行 `<imageN>：<用途>`；用途不以句号等结尾时补“。”。
5. 本页文本非空时输出 `本页描述：` 加原文。

图片编号规则：

- 最终图片序列 = 角色（引用顺序）→ 场景 → 本页附图；来源内部沿用现有解析（默认首张，手动选择
  按保存的 ID 列表）。先定序列再从 1 编号，不上传文件内容复用改变逻辑位置。
- 全部输入只有一张图时，说明行用“参考图：……”代替 `<image1>`；多图用 `<imageN>`。
- 没有任何图片则省略全部图片说明；无图的角色／场景仍输出名称和文字。
- 合计上限 10 张，超限阻断，不静默截断。

输出 `positive_prompt` 为拼接文本，`negative_prompt` 恒为空字符串：不做 AVOID 转换，用户自行
输入的否定句当普通文字保留。来源追踪 `sections` 记录每段的 kind
（global／character／scene／attachment／page）、来源、prompt_name、文字与图片 id，供生成详情分段。

编译示例（多参考图）：

```text
希格莉德：
<image1>、<image2>：希格莉德的身份与服装参考。
角色子设定文字，或本页整段覆盖。

咖啡馆：
<image3>：咖啡馆的环境外观参考。
场景子设定文字，或本页整段覆盖。

<image4>：画风参考。

本页描述：
希格莉德坐在窗边，望向窗外。半身侧面镜头。
```

## 审计

审计只保留必要检查，错误硬阻断，警告集可以为空：

- 引用的角色／子设定／场景缺失；
- `text_overrides`／`reference_overrides` 含不匹配当前引用的 key（保存时拒绝）；
- 参考图合计超过 10 张；
- 参考图文件缺失；
- 格式错误（含 `positive_prompt` 为空）。

不再有分类、词库命中、`{标签}` 圈选、逐词权重、人数语义、重复词、正负冲突或 tag 预算检查。
词库 API 保留供独立查询与训练使用，生成路径不使用词库。

Prompt 草稿可以带审计错误保存。所有向 ComfyUI 提交新采样的生成入口在服务端按同一投影重新编译
与审计：错误硬阻断；浏览器预检和 CLI 不能绕过门禁。

## 编写规则

普通制作交付方便用户精修的原型；完整流程见[创作指南](../creative/guide.md)。
编辑前用 `prompt.read` 完整读取并核验本次涉及的模型范围；不要求读取组装后的全文。
需要理解上游引用、覆盖或排查最终输入时再查询 `prompt.context`，具体入口见[Agent 接口](agent-interfaces.md)。

Prompt 只表达目标方向，不增加细节，不拆解动作的身体实现过程。动作名足够时只写动作名，例如
`looking back`；需要关系时用简短自然语言，例如 `she looks back at the doorway`。不追加身体部位、
角度、动作步骤或伴随姿态，不以确认稿、必要性或纠正细微姿态为扩写例外。

页面动作／关系描述每条最多 20 个英文单词，不得拆成多条绕过。这是 Agent 编写约束，不是保存或
生成门槛，不自动截断用户输入。外观与基础场景不套用此上限，但同样不得擅自增加细节。

同一环境优先引用共享场景，页面只补局部差异；一次性环境直接写本页。不写时间过程、解释、创作
意图或不可见心理活动。多角色页面在本页描述中按实际归属写清动作主体；画外对白 speaker 不会进入
画面角色或 Prompt。

子设定的文字与参考图自包含：新形态从最接近的既有形态出发，复制后只改已确认的造型差异及直接
冲突项，自包含不等于从头重写。新增子设定先向用户说明用途和区别，经同意后建立，再以简洁验证图
交用户验收后使用；已有配置或页面调整能满足需要时优先复用。需要改变故事或视觉方向时先讨论，
不用堆词掩盖冲突。

共享 render profile 不属于普通项目制作的 `*.prompt.json` 写入。只有用户另行授权仓库级维护
任务时，Prompt Agent 才按该资源的实际契约处理；不要在页面制作中顺手修改。

## 写入流程

先理解本次涉及的页面内容和引用，准备修改时用 `prompt.read` 读取当前范围的正文和指纹。
具体目标、保存参数与批量操作由工具帮助统一维护：

```powershell
node C:/Workspace/story-canvas/app/scripts/story-canvas.mjs help prompt
```

角色、场景与页面都使用 `prompt.read/save`，需要查看继承词时按需查 `prompt.sources`，
排查完整生成输入时再查 `prompt.context`。不要把只读展开内容写回页面，也不再使用旧完整 Prompt 草稿入口。

保存校验当前范围及必要上游版本，在最新文件中更新该范围。busy 可以短暂退避后有界重提；
目标或依赖版本冲突必须重新读取和判断，不能只换新指纹重放旧修改。
成功返回更新后的范围及新保存参数。附带的审计不代表全部下游页面已经通过；
编辑非活动模型时不冒充已按该模型完成生成审计。

`audit.status: "complete"` 表示审计已经执行，`valid`、`errors`、`warnings` 是实际审计结果；
编译自身的缺件或配置问题另见 `diagnostics`。`status: "unavailable"` 表示有效配置或必要上下文
不可获得，应先处理 `diagnostics`，不能视为通过。

后置审计有错误或未完成时，事实仍已保存，命令退出码为 0；只有保存本身失败
才使用非零退出码并保留未消费会话。Agent 应阅读 `audit` 决定修正，不要把退出码 0 当成渲染许可。
后续事实或配置变化后 render 会重新审计，不复用写入时的报告。

Prompt 文本只在当前确认范围内调整，不自动把旧视觉说明重新翻译成详细要求，也不扩大到范围外旧页。
新增子设定和实质角色改动遵守用户验收流程。LoRA 的新增、删除、替换须经用户同意；生成配置的风格 LoRA 与独立
训练的任何变更仍需用户明确同意。

## 生成与验证

剧情总览的生成预览将“尚无候选”与“已有候选但无相符结果”分别计数，两类都属于补齐范围。
逐页“查看详情”打开二级窗口，按需读取候选生成记录，对比当前已保存的最终文本，
列出实际文字变化；比较对象是旧候选，不是最近一次编辑前的页面。

服务端把全局 `prompt.text`、各引用设定的生效文字、参考图和本页文本确定性组合。缺失引用、
override key 不匹配、图片缺失或超限、配置冲突等审计错误会阻止渲染。

渲染使用当前持久 Prompt，不接受临时正负向文本或任意参数覆盖；受控对照可通过现有 --seed 指定种子。单任务允许一至三张，通常三张：

```powershell
npm --prefix <仓库根>/app run visual:produce -- render page <project-id> <page-id> --count 3 --wait
```

以候选验证表达是否有效。失败时区分 Seed 波动、Prompt 表达、页面承载和主观方向；不要继续追加
无法归因的文字。需要比较两个方案时，Prompt Agent 依次通过正常 read/save 保存一个明确的当前
方案并生成候选；切换方案时全量改写相关文本，不保存临时差分或父子链。

候选匹配以最终实际输入为准：改 Prompt 名称、附图用途、生效文字、图片内容／顺序或生成参数都
影响匹配；仅显示标题（title）改变不影响生成的，不使候选过期。未生效的上游文字变化不影响使用
整段 override 的结果。

当前范围内已准备好的独立页面可并发提交。默认每页三张且全部保留；至少两张严重出错时最多修正一次并再生成三张，之后交用户，不按审美持续补样或筛选。详见[视觉页面参考](visual-pages.md)。

新增子设定先获用户同意，单独出验证图并由用户验收后才能用于页面；已有已验收且未变配置复用。实质修改已验收配置也先验证受影响部分，不能用 Agent 审美判断替代用户确认。

对比实验可从无参考图页面一次性导入编译后的单段文本，或建立自由文本输入；带参考图页面的导入
仍明确不支持。
