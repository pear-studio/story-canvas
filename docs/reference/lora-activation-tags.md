# LoRA 激活标签指南

激活标签也称触发词，用于在生成 Prompt 中调用 LoRA 学到的概念。它是可选的训练策略，不是
文件名、资源 ID 或随机种子。

## 基本原则

- 不自动生成随机字符串；项目内唯一不代表文本编码器能稳定理解。
- 标签可以留空。画风、整体质感和部分通用概念通常可以只靠加载权重生效。
- 需要标签时，选择简短、可读、低冲突并与概念有关的写法。
- 一个 LoRA 可以有多个标签，但每个标签都应对应一个需要独立调用的概念。
- 标签只写入实际包含对应概念的图片 Caption，不机械加入全部图片。
- 普通质量词、动作词、负面词和推荐 Prompt 不属于激活标签。

## 按训练目标选择

### 已知角色

底模已经认识该角色时，优先采用模型生态中的规范角色标签和作品标签，以利用底模先验。需要
隔离特定版本或设计时，可以另设可读、低冲突的别名。

### 原创角色

使用稳定、易记的罗马字名字，或“项目缩写加角色名”。不要只用 `girl`、`man` 等宽泛类别词，
也不要把 UUID 当作默认标签。

### 服装、道具和场景

底模已经理解且只需强化时，可以沿用现有语义标签。需要在同一个 LoRA 中独立开关某套服装、
道具或场景时，再为它设置单独的可读标签。只有标签没有足够的数据变化，不能真正解耦概念。

### 画风和整体质感

通常可以不设置专用标签，加载 LoRA 权重本身就是开关。只有需要与其他 LoRA 叠加并独立控制
时，才增加可读的风格标签。

### 多个子概念

只给需要独立调用的子概念设置标签。每张图片只写实际出现的标签；共现图片可以同时写多个。
如果两个概念在数据集中始终共同出现，增加两个名字也不能保证模型把它们分开。

## 激活标签与每张图片的 Caption

激活标签是“调用 LoRA 的入口”，不是必须附加到每张 Caption 的通用质量词。对于角色 LoRA，
先决定身份由哪个标签承担，再决定固定外观是否需要作为显式控制项：

| 目标 | 默认建议 | 需要特别检查 |
| --- | --- | --- |
| 已知角色 | 可保留底模认识的规范角色／系列标签 | 规范标签本身可能已经携带完整身份先验，不要再叠加一串随机别名 |
| 原创角色 | 使用一个稳定、低冲突的可读触发词 | 触发词和每张 Caption 的固定发色、发型、眼睛是否重复绑定 |
| 服装、道具、场景 | 只有需要独立开关且数据有变化覆盖时才设置标签 | 始终和角色共同出现的数据无法保证真正解耦 |
| 画风 | 通常让权重本身承担开关 | 不要把风格词误当角色身份词，也不要把画风标签机械写入所有角色 Caption |

激活标签可以出现在实际包含该概念的 Caption 中，但系统不应因为 `activation_terms` 有值就自动
追加文本。尤其是“触发词拥有固定身份特征”的训练，重复写入稳定发型或脸部特征会减少服装、动作
和构图的可变性；反过来，如果目标就是训练一个可显式调用的服装或角色版本，也可以保留这些标签，
但必须在训练快照或实验说明中记录这个选择。

当前唯一训练路线是 Qwen-Image-2.1；数据集 Caption 原样使用，标签或自然语言均可，内置打标器
产出 Danbooru 风格标签并保留下划线。
`activation_terms` 是数据集目标概念的调用入口，不是某一份 LoRA 权重的 ID；一个训练项目拥有
一份素材集合与唯一当前设置，训练时把激活标签和素材快照写入各次 run，再据此登记资源。当前不再为模型家族
维护不同的 Caption Profile。

## 使用检查

触发词不是可以无损重命名的别名。替换触发词或移除原有作品词后，分别检查提示词本身的响应和加载 LoRA 的额外收益；新词与旧词共同出现在 Caption 中，不保证新词能够独立替代旧词。比较调用方式时保留对应无 LoRA 条件，避免把底模已有的词响应归因于训练。

图片集合确定并保存后，Agent 根据训练目标、素材覆盖和确切模型家族提出标签方案，并说明每个
标签的用途。工作台预检只在“已声明标签未出现在任何启用 Caption”时提示；没有设置标签本身
不是错误。Agent 将选定权重登记为正式 LoRA 时，再从训练快照整理标签和用途写入资源记录。

Caption 的编写、模型家族差异和完整训练协作见 [LoRA 训练](lora-training.md)。
