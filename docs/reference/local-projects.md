# 本地项目管理

工具代码与创作资料分别管理。正式剧情项目、训练项目放在工具仓库外，各自使用独立本地 Git；不要求远程仓库或 Submodule。

## 目录边界

| 位置 | 内容 | 管理方式 |
|---|---|---|
| 工具 `app/`、`library/`、`docs/` | 应用、全局资源、开发文档 | 工具 Git |
| 工具 `Config/local.json` | 服务、模型与 Python 路径、凭据 | 本机配置，单独备份 |
| 工具 `Config/projects.json` | 项目 ID、类型、绝对路径、临时标记 | 本机登记，单独备份 |
| 工具 `workspace/` | 工作台新建或复制的临时项目 | 忽略，不自动删除，不初始化 Git |
| 工具 `Saved/` | 缓存、日志、实例状态、对比实验、Agent 临时工作 | 忽略，任务空闲后可清理 |
| 正式剧情项目 | 设置、剧情、角色、Prompt、`materials/` | 项目 Git |
| 项目所属资料 | `writing-corpus/`、`resources/loras/` 元数据与图片 | 只在所属项目保存一份，进入其 Git，其他项目显式读取 |
| 正式训练项目 | `project.json`、`settings.json`、`assets/`、`captioning/`、必要参考资料 | 项目 Git |
| 项目 `Outputs/`、`Training/` | 剧情图片、训练冻结输入与结果 | 忽略，随项目单独备份 |
| 项目 `Saved/` | 执行副本、缓存、临时状态 | 忽略，任务空闲后可清理 |

`Saved/` 中的对比实验和拼图也是临时结果。需要长期保存的验收图片应另行导出备份。模型权重仍在配置的外部模型目录，清理项目不会删除权重。Python 环境在 `app/data.local/`，按[环境搭建](setup.md)用 uv 重建。

## 工作台操作

顶栏项目名称下拉列表按「剧情项目」「LoRA 训练项目」分组，可搜索名称。条目只用于选择项目，附简短 Git 状态；不提供卡片管理菜单。列表底部的「添加项目」按钮登记已有文件夹。

剧情项目打开后直接显示基本信息（名称、登记的真实路径、Git 详情）。左下「项目」弹出菜单直接选择基本信息、生成设置、参考材料和任务历史；嵌字设定只保留在「输出」。菜单下半部集中管理当前项目，训练项目选中后也显示适用的管理操作。没有独立项目管理窗口。

- **添加项目**：点击项目列表底部的「添加项目」，输入含 `project.json` 的绝对目录。训练项目还须有 `settings.json`。只登记，不复制；成功后打开该项目。
- **复制临时项目**：复制当前事实与输入到工具 `workspace/`；不带旧 Git、生成结果、训练历史或缓存，复制完成即可打开。
- **提升为正式项目**：为临时项目指定不存在的外部目录，完整复制并核对文件，再初始化 Git；保留临时项目本次产生的成果，成功后移除临时目录。
- **重新定位**：仅保留 Agent 接口，目录移动后由 Agent 更新登记。页面没有重新定位按钮；失效条目仍显示在列表中。
- **移除登记**：只从本机列表移除，保留文件和 Git。
- **删除临时项目**：仅对工作台 `workspace/` 直接子目录开放，执行前确认；正式项目不提供文件删除操作。

后台通过登记定位项目，不扫描磁盘发现项目。`Config/` 不能随 `Saved/` 一起清理；登记丢失后可以重新打开已有目录。

接口为 `GET /api/project-library`、`POST /api/project-library/open`（`{ "path": "绝对目录" }`），以及 `POST /api/project-library/:id/{copy|promote|relocate|forget|delete}`；提升和重新定位携带 `path`。项目生命周期操作与事实操作串行，活动任务未结束时不复制、提升或删除项目。

## 项目 Git 状态

项目列表每个条目附 Git 图标：绿色表示干净，琥珀色表示有改动或本地引用差异，灰色表示未初始化／不可读取。未关联远程（含未初始化）仅用「本地」标记；浅米色底专用于临时项目，不再显示临时文字；悬停显示简短摘要，重新展开列表刷新。基本信息页保留完整 Git 详情。忽略文件不列入改动，临时项目不会借用上级工具仓库的 Git 状态。

页面与 Agent 共用 `GET /api/project-library/:id/git`，按登记路径只读查询，不初始化仓库、不 fetch、不提交或同步。成功返回 `status: ready`、`branch`、`commit`、`upstream`、`ahead`、`behind`、`dirty`、`changes`、`remotes`；没有仓库为 `not_repository`，读取失败为 `unavailable` 并带 `message`。未登记 ID 返回 404。改动状态为 Git porcelain 两列（暂存区、工作区，`.` 表示无变化，`??` 表示未跟踪）；重命名带 `original_path`。远程 URL 不回传内嵌凭据。

领先／落后仅相对本机保存的 upstream 引用，不能据此断言远程服务器最新状态。提交、拉取和推送由用户委托 Agent 后通过现有 Git CLI 完成；工作台不提供 Git 写操作按钮或接口。

## 训练项目

左侧训练项目列表下方的「全部训练记录」汇总所有项目的历史运行，不受当前所选项目限制；项目内部的「训练记录」仍只显示该项目。全局入口可直接通过 `?tab=lora-history` 打开。

一个训练项目拥有一份素材集合和唯一当前 `settings.json`。创建素材项目时一并建立默认设置，编辑设置不创建新方案；启动训练时冻结当时的素材、Caption 和设置，形成新的 run。以后修改当前设置不改变旧 run。

现有接口用 `/api/lora-training/datasets/:id` 表达素材视图，用 `/api/lora-training/tasks/:id` 表达同一项目的设置视图，两者 ID 相同并共享 ETag。`tasks` 不是独立方案集合，不提供新建方案接口。历史归档保留原 run ID 和冻结元数据，只读查看不要求当前配置与历史配置一致。

## 备份与迁移

Git 保护文本和素材的修改历史，不能代替异盘备份。正式项目目录（含需要保留的 `Outputs/`、`Training/` 和 `.git/`）、`Config/`、外部权重分别备份。换机器后恢复目录，安装工具依赖，再通过工作台重新定位项目并调整本机环境配置。
