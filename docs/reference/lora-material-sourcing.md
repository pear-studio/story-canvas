# 角色素材搜寻参考

用于 `lora-material-sourcing` 的社区检索与原图回溯。搜寻阶段交付原始图片供用户筛选；用户确认后的导入、裁剪与分组见 [LoRA 训练](lora-training.md#筛选后的图片整理)。

## 检索与回溯

- 先核对角色的中、英、日文名及作品名，再组合角色名、作者名和站点检索。搜索摘要、图站标签和作者填写的标题只是线索，图片本身才是身份、造型和质量的证据。
- Wiki、图站标签页和社区转载可以提供批量索引；沿作品来源链接回到官方资源或作者页，优先下载原图。同一作品的缩略图、无眼镜差分、不同尺寸或转载版要按独立画面信息判断，不按文件数累积。
- 搜索结果不等于完成采集。交付前实际下载、解码、目视核验并去重；子 Agent 的结果也要纳入同一轮最终复核，不能直接按其报告数量累加。
- 将作者、作品页、原图地址和最终文件名关联保存在临时采集区。没有取得作者原图时，如实注明转载或视频封面来源；封面可能裁过画幅，不能当成完整作品原图。
- 留意作者明确标注的使用限制。为训练搜集时，不把明确标注禁止 AI 使用的作品加入训练候选；未见限制也不等于已取得作者授权。站点 AI 标记只能辅助筛选，不能证明作品一定是人工绘制。

## 本次验证过的获取线索

以下是 2026-09 素材搜寻中成功使用的方法，属于站点实现线索，不是工作台功能或长期可用保证。响应字段、访问条件变化时以实际结果为准，不凭示例猜测图片地址。

| 来源 | 可尝试的入口 | 核验重点 |
|---|---|---|
| Pixiv | 已知作品 ID 后，公开 `/ajax/illust/{id}` 与 `/ajax/illust/{id}/pages` 曾可取得作者、限制标记、页数及 `urls.original`；下载原图使用正常浏览器 User-Agent 与 `Referer: https://www.pixiv.net/` | 下载响应中的原图地址；多页作品逐页判断独立价值，不把首页当作整部作品，也不机械全收 |
| Zerochan | 标签页或条目页追加 `?json` 曾返回索引、`full` 与 `source`；本次标签 URL 的空格使用 `+` 成功 | 优先沿 `source` 回到作者页；只取得 `full` 时注明图站转载，不能称为作者直取 |
| Bilibili | 作者动态、图文页的公开图片资源曾提供 `i*.hdslb.com/bfs/new_dyn/` 原图；绘画过程视频封面可作补充线索 | 比对作者页、画幅与实际尺寸，区分原作、封面、MMD／社区 3D 和游戏截图 |
| 官方资源页 | 公告、壁纸页可能链接共享文件夹或媒体包 | 查看链接中的完整资源目录，不只保存公告内嵌预览；仍要检查是否复用同一立绘 |

## 访问失败与视频

- 米游社页面失效、空列表，或其他站点返回 403 时，先区分“没找到作品”和“当前访问不到”。改用作者其他公开发布渠道、索引来源或可访问的原图链接；少量验证后仍失败就记录限制，不反复请求同一失败入口。
- Reddit 帖子、API 和图片 CDN 的可访问性可能不同；某个入口失败不能据此断言整个来源没有素材。替代来源仍须核对是否为同一作品。
- 海外爆料与测试服演示需要独立标明版本不确定性。优先找源视频与可用的最高质量流，再按可辨认的姿势和镜头变化选帧；不要按整分钟等固定间隔抽帧充数。
- 720p／4K 是画幅尺寸，不是人物细节保证。战斗远景、特效盖脸和严重压缩常常不如较小的清楚近景；先看帧再决定保留，必要时只交付视频链接。
- 角落签名、文字或 UI 不自动导致淘汰，也不能保证之后可无损移除。搜寻阶段保留原图；裁剪会伤及头发、手指或服装结构时，将限制交代清楚。
