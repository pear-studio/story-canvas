# Prompt 编辑规范与接口改进方案

## 状态与目标

本文记录本次讨论确认的目标和建议实施顺序。三批实现已完成，当前验证和提交状态见末尾实施进展。方案已获实施授权，按三批实现、验证、独立 review 后分别提交；不生成图片、不推送。用户补充允许分类合并带来的合理、预期词序变化，优先实用与效率，不建立严格保序机制。

目标是让 Agent 写出简短、可继续编辑的 Prompt，让用户保持当前以本页差异为主的编辑体验，并消除 Agent 自行拼装继承上下文造成的遗漏。

本方案讨论通用数据结构、编辑器和操作规范。既有项目文本仅在契约迁移时机械转换，不开展内容重写或创作优化。

## 已确认范围

1. 控制器支持的镜头必须通过机位控制器设置，保存可恢复的 `camera_settings`；未覆盖的必要表达另行补充。未来有真实需求再扩展控制器。
2. 外观与动作统一为“人物”，网页、Agent 接口、存储和编译使用同一分类；保留单来源作者顺序，允许统一分类造成的合理跨层重排。
3. 片段按实际编辑需要分组，不逐标签拆分。头发相关内容可以合成一条；基础场景通常可以合成一条；需要独立开关、调权时再拆。
4. 标签优先自动识别，必要时使用 `{}` 明确标记；选中文本后输入 `{` 自动包围选区，不替换原文。
5. Prompt 只表达目标方向，不增加细节，不拆解动作的身体实现过程。动作名足够时只写动作名，关系使用简短自然语言。
6. 页面动作／关系描述每条最多 15 个英文单词，不得拆条绕过；不保留“必要时”或“确认稿指定”等扩写例外。外观与基础场景不套用此上限，但同样不得擅自增加细节。
7. 长度是 Agent 编写约束，不增加保存或生成门禁，不自动压缩用户文本。
8. 提供面向编辑的完整读取入口：本页可编辑内容、继承来源、各层调整、关闭项、最终生效结果。明确区分可写事实与只读上下文。
9. Agent 编辑页面 Prompt 前使用完整读取入口，不能仅凭本页文件或局部 `prompt read` 判断完整输入。

以下行为保留：

- 上游权重／开关修改统一重置下游对应调整；实际影响输出时展示影响并确认。
- 同一环境优先引用共享场景；页面补局部差异，一次性环境可直接写在本页。
- 继承词独立折叠，本页编辑区突出局部内容。
- 同一作用域内完全重复片段继续阻止生成，不增加语义相似拦截或新的警告流程。
- 保持事实 read/save 指纹保护、LoRA 独立授权、候选保留和当前生成数量规则。

## 调查依据

- `app/src/prompt-person-category.ts` 将 appearance/action 合并展示，再按旧 appearance 数量切回两个数组；当前分类归属部分取决于历史槽位。
- `app/server/fact-drafts.mjs` 的 read 返回可编辑正文和指纹，不返回展开后的继承上下文。上游 hash 能保护提交，不能代替阅读上游内容。
- `app/scripts/visual-production.mjs` 已有 `preview page`，不是缺少最终预览能力。
- `app/server/page-render-inspection.mjs` 预览同时承载 Prompt、模型、LoRA、工作流和诊断；最终片段过滤禁用项，不直接呈现完整的调整过程。
- `app/server/current-page-prompt.mjs` 和 `app/shared/prompt-inheritance.mjs` 已有继承及调整逻辑，新增读取入口必须复用这些规则。
- `.agents/skills/prompt-authoring/SKILL.md` 已要求看最终编译结果，但读取路径不够集中，且残留机位参数位于 `display_text` 的过时说明。

## 第一批：明确编写规范，补齐花括号输入

### 改动内容

将已确认的简洁写法、片段分组、标签混写、场景复用和机位使用要求写入规则及专项文档。

使用可执行的约束表述：动作名称足够就只写名称；需要表达关系时说明主体、动作和对象；不追加身体部位、角度、步骤、伴随姿态。不用“保证自然”“必要时细化”等条款重新开放扩写。只处理主体、主要动作、关键关系等明显偏差，不以细小姿态问题为由扩写。

15 词限制适用于自然语言动作／关系描述，不因第二批合并为人物分类而扩展到所有人物词。一个关系描述即使包含标签标记，仍作为同一描述受约束；不能将一段扩写拆成多个片段规避。不新增计数字段、审计器或自动截断。

输入编辑器在非空选区下收到 `{` 时插入成对花括号并保留选中文本。正向、反向选区行为一致。空选区维持现有输入行为；中文输入法组合过程中不抢占输入。复用现有编辑通知和撤销机制，保证父组件草稿、光标与标签标记刷新一致。

### 主要位置

- `AGENTS.md`：仅保留核心原则，细则引用专项文档。
- `docs/creative/guide.md`、`docs/reference/prompt.md`。
- `.agents/skills/prompt-authoring/SKILL.md`，必要时同步其他直接相关专项技能的重复表述。
- `app/src/InlinePromptInput.tsx` 及其现有浏览器测试。

不调用 agent-sync，不手工编辑 CLAUDE.md 或本地技能投影。完整读取入口尚未实现，本批仍明确使用现有 preview 检查，不提前把目标能力写成当前能力。

### 验收与提交

- 选中 `long hair` 输入 `{` 得到 `{long hair}`；跨已有标签展示节点选区时不丢文本。
- 验证反向选区、只读状态、输入法组合及编辑撤销行为；复用现有浏览器用例，不新增单独框架。
- 检查文档不再要求逐标签拆条，也不再使用旧机位参数字段。
- 运行类型检查、相关 Prompt 浏览器测试及完整测试。
- 建议提交：`feat: 明确 Prompt 简洁规范并支持选区标签包围`。

## 第二批：统一人物分类与当前资产契约

### 改动内容

将人物分类正式存为 `person`，当前六类变为 `subject/person/setting/camera/avoid`。角色 identity、variant、剧情页和角色视觉页使用一致契约。场景仍仅允许原有环境与负向内容，不因统一分类扩大其职责。

单文件转换以旧 appearance 数组后接 action 数组作为候选映射，保留片段 ID、文本、权重、启停、角色绑定及原数组内顺序；迁移允许下述跨继承层的预期词序变化。保留所有继承调整、机位参数、场景引用和 LoRA。删除按历史槽位拆分的网页转换逻辑，不长期保留两套分类格式。

同步更新生成配置的分类顺序、词库类别到编辑类别的映射、来源投影和诊断定位。外部词库自身的标签分类不需要因 UI 分类更名而改写。

### 顺序与分段控制

迁移前扫描当前身份／子设定组合，先验证跨继承层的排序。当前编译顺序可能是“身份 appearance → 子设定 appearance → 身份 action → 子设定 action”；逐文件直接合并后可能变成“身份 appearance → 身份 action → 子设定 appearance → 子设定 action”。这会改变真实词序，不能只当作分段变化。先列出实际受影响组合，并用身份、子设定同时含两类内容的最小案例验证。采用身份 person → 子设定 person 的单一路径，允许这种预期重排，不增加隐藏旧分类。

对实际迁移清单内全部现有页面记录迁移前后的正负向文本、按顺序排列的生效片段、LoRA 身份及结构化基础 hash，包括被忽略的本地项目。比较角色归属、权重、启停和负向内容，特别检查未绑定内容原先按 appearance/action 分段的情况。分类名称、来源路径变化可以列为预期元数据差异；词序与分段的预期变化可记录后接受；片段遗漏、归属、权重、启停或 LoRA 变化必须修复，不能以词序调整为由放行。

“保留词条顺序”不等于“最终文本逐字相同”。合并分类可能改变换行边界，也会影响自定义模式的基础 hash、候选匹配和冻结任务契约。允许统一契约带来的预期分段变化，记录差异和受影响范围，不为保留旧槽位建立长期隐藏分类。

### 主要位置

- `library/schemas/` 中页面、角色、场景、Prompt policy 相关契约。
- `app/server/prompt-contract.mjs`、`story-files.mjs`、`character-files.mjs`。
- `app/server/current-page-prompt.mjs`、Prompt 审计和来源投影。
- `app/shared/prompt-inheritance.mjs` 及继承事实处理。
- `app/src/PromptFragmentEditor.tsx`、`prompt-person-category.ts`、总览、继承区及客户端类型。
- 项目创建器、模板、示例、当前生成配置及相关测试 fixture。
- 当前受管项目与本地项目中使用旧契约的事实文件。

### 迁移边界

先检查 `git ls-files`、根白名单和本地项目清单，列出实际目标；受管项目不得初始化独立 Git。本地事实使用现有语义入口或受控一次性迁移工具完成，不能用临时脚本随意直写项目 JSON。若旧接口不能保存新契约，迁移需作为明确的维护操作提供校验、范围清单和失败回退。

迁移前确认没有活动写入及排队任务；不自行取消用户任务。不删除 generated、runtime 或外部模型目录，不改写旧候选的历史生成记录。自定义覆盖及冻结任务需要单独检查，不能静默更新确认 hash 来掩盖输入变化。

机械转换的受管事实与代码同批提交，避免仓库 HEAD 中代码与事实格式不一致。本地被忽略资产只报告迁移结果，不强行纳入根 Git。

### 验收与提交

- 单角色、多角色、未绑定词、角色视觉页、场景继承及负向内容的编译语义保持。
- 浏览器人物区排序和绑定保存后与 Agent read 一致，不再依赖旧数组长度。
- 继承覆盖、上游重置与完全重复阻止规则保持。
- 项目创建和当前项目校验通过；对迁移后的编译差异逐项归因。
- 运行类型检查、相关领域与浏览器测试、完整测试。
- 建议提交：`refactor: 统一人物 Prompt 分类与项目契约`。

## 第三批：面向 Agent 的完整编辑读取入口

### 改动内容

提供完整 PageKey 定位的编辑上下文读取能力，覆盖剧情页与角色视觉页，复用当前事实读取和 Prompt 解析链。服务端生成结果，不让 Agent 或 CLI 客户端重新拼装继承。

返回内容分为明确的几部分：

- **可写草稿**：沿用现有 read/save 正文、目标身份和目标／依赖指纹，可直接用于对应 save。
- **只读来源**：实际参与的角色 identity、variant、共享场景和有效生成配置基础词及触发词。
- **调整过程**：子设定对身份的调整、本页对角色和场景的调整；展示上游值、调整值和最终值，关闭项仍保留并标明不参与输出。
- **最终结果**：实际生成模式、最终正负向文本、词条来源与审计结果。自定义模式不得将结构化基础冒充实际生成输入。
- **不完整诊断**：缺少依赖时明确标记哪部分无法解析，不能把空结果伪装成完整上下文。

有效生成配置必须包括项目 `render-profile.override.json` 的结果，避免只解决角色 inheritance 却继续漏掉配置覆盖。输出精确限于当前页面实际依赖，不展开角色全部子设定、全项目页面或候选历史。

### 接口组织原则

在现有 Agent/页面领域入口中提供具名读取操作，具体 CLI 名称在实现时沿用现有命名风格；不再增加一套通用查询语言。

可写草稿与只读上下文在响应中分离，保存仍复用现有 save 契约。文档给出一次完整读取、修改草稿、提交的可复制示例，避免 Agent 将展开后的上游词写回本页。

在一致的事实读取边界内捕获参与文件，返回与草稿指纹对应的上下文，不让多次客户端调用产生混合版本。只读读取不要求模型文件可用、不启动 ComfyUI，不把完整环境诊断与工作流详情塞入默认响应；生成就绪检查继续由现有 preview/render 承担。

不复制继承计算算法，不持久化展开后的 Prompt，不新增上下文缓存事实或页面“已读”状态。已有网页预览和生成流程尽量保持原接口。

### 主要位置

- `app/server/fact-drafts.mjs`、`agent-http.mjs` 及相关领域事实读取。
- `app/server/page-render-resolver.mjs`、`current-page-prompt.mjs`、继承与有效配置解析模块。
- `app/scripts/` 中相应 CLI 入口。
- `docs/reference/agent-interfaces.md`、`docs/reference/prompt.md`、创作指南和 Prompt 技能。

规则明确：编辑页面 Prompt 先读完整上下文；原始文件可用于排查，不能替代完整内容判断。同轮上下文未变化时不重复读取；依赖冲突后重新读取判断。保存后继续检查 audit，生成前继续检查 preview。

### 验收与提交

- 覆盖身份 → 子设定调整 → 页面调整的实际优先顺序，正确显示关闭和重新开启。
- 场景及其页面调整、生成配置项目 override 均进入有效结果。
- 最终文本与现有实际编译路径一致；来源和关闭原因可追踪。
- 返回的可写草稿可原样用于现有保存流程，旧指纹仍会拒绝冲突，不写入只读展开结果。
- 缺少本机模型时仍能读取有效事实与文本；缺少解析依赖时返回明确不完整诊断。
- 两类页面均通过；网页继承区继续折叠，没有被迫改成合并展示。
- 运行类型检查、相关领域测试和完整测试。
- 建议提交：`feat: 提供包含继承与覆盖的 Prompt 编辑上下文`。

## 验证与交付节奏

每批先运行最小相关验证，收尾运行一次完整测试。修改测试前读取 auto-test-guard 技能，优先扩展现有行为用例，避免按内部函数逐个补测试。

Windows 当前仓库命令：

```powershell
npm --prefix D:/Workplace/story-canvas/app run check
npm --prefix D:/Workplace/story-canvas/app run test:prompt-ui
npm --prefix D:/Workplace/story-canvas/app test
```

`test` 已包含类型检查与构建，最终验证不额外无理由重复运行。项目校验按脚本当前参数和实际迁移目标执行，不猜测路径。Node 版本以 `.node-version` 和 package.json 为准。

方案写完后，以及每批实现完成、提交之前，各安排一个独立 subagent review。方案 review 检查已确认范围、批次依赖和遗漏；实现 review 检查实际 diff、行为契约、迁移证据与验证结果。处理有依据的问题，并对实质修正做相关复验；review 不能代替测试。发现无法自行解决的实质冲突时才回到用户讨论，不把日常 review 变成逐批重复授权。

每批交付改动摘要、验证结果、review 结论、实际迁移范围及剩余问题，再创建该批提交；提交只包含本批已验证内容，不顺带整理无关模块。失败先修复当前批，不带着契约不一致进入下一批。

完成后将稳定事实归入现有参考和开发文档；本方案不成为新的长期规则来源。无需重新讨论已确认的取舍。只有发现无法保持约定行为的实质冲突时，带具体差异回到讨论。
