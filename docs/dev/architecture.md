# 架构与生成实现

本文维护组件、并发和生成资产边界；开发取舍与验证见[开发指南](guide.md)。操作参数查工具 help，项目目录见[项目事实](../reference/project-files.md)。

## 组件与数据流

| 组件 | 职责 |
|---|---|
| 外部 Agent | 讨论、语义编辑、调用工具、判断成果 |
| React `app/src/` | 导航、显式草稿保存、媒体和全局工具 |
| Node `app/server/` | 事实校验与保存、确定性编译、资源、任务和媒体 |
| 模型适配器 | 原生输入、编译及专用编辑器 |
| ComfyUI | 消费实例化工作流，生成图片／视频 |
| 训练模块 | 素材与设置、冻结计划、子进程及训练媒体 |

单个 Node 服务持有事实写入；开发挂 Vite 中间件，生产提供 dist。HTTP Adapter 只解析并调用领域入口。

```text
项目事实 + 可复用配置 → 编译与冻结 → 队列 → ComfyUI → 候选 → 显式成品
```

页面由完整 PageKey 定位，归属和顺序由 index 管理；content、各模型 Prompt 和 render 独立保存。适配器只消费活动模型；内容描述不隐式写入 Prompt。

目录和搜索用统一小图标区分文字、图片、动态与分镜页。文字不显示候选数，图片显示候选张数，分镜只显示格数。目录与剧情总览的动态摘要显示候选段数及最新候选处理后的时长：用实际帧数、帧率和页面已保存的裁剪／倍率按同一帧边界计算，保留两位小数；未生成、时间轴缺失和裁剪无效分别提示，不用生成配置冒充实际时长。数量索引同时提供最新候选时间轴，不额外扫描媒体；动态页的候选列表按已应用参数显示各候选处理后的秒数。

剧情总览保留阅读目录，支持全文、章节、单元范围内按页面类型集中浏览；筛选保留原页码和章节来源，范围与类型写入导航 URL。工作台按项目、范围和类型保留纵向、卡片横向及阅读目录的滚动位置；跨页后退、前进及切回类型时恢复，卸载归零和后台刷新不覆盖已存位置。卡片只轮询可见媒体，分镜按已保存的各格选图和裁切预览整页。批量生成／移除直接显示，操作当前筛选结果；文字不参与，分镜展开到各格，扫描确认后才执行。

分镜页沿用独立 PageKey 生成单格，目录投影隐藏带 `parent_page_id` 的内部格子。`comic-layout.mjs` 统一切分几何，生成提交据已保存布局冻结单格尺寸；整页成品冻结各格选图、裁切和嵌字后确定性合成。图片按格裁切，文字使用单格相对坐标并允许跨格，字号以画布短边的 1024 单位为基准，竖屏保留原有大小，分镜按整页短边统一；普通预览、全屏、译文检查与成品输出复用同一换算。

分镜工作台的“整页”标签维护合成布局与预览，各分镜标签直接复用普通页面工作区和候选交互；切换时保留草稿，只有当前标签响应快捷键。候选通过“用于整页”明确选图，分镜保存同时提交待保存的整页设置。

页面通过 `use-page-changes` 注册保存入口，切页统一提供保存、放弃或取消；整页布局、隐藏分镜草稿与译文都纳入未保存检测，保存失败不导航。`use-draft-history` 维护当前编辑身份的草稿撤销／重做，连续输入与拖动合并为一步；新增分镜造成的身份变化建立新的历史边界。整页与分镜使用相同的字号换算；布局和嵌字模式切换控件及交互。全屏合成画布复用 `ImageLightbox` 的缩放、拖动、触屏和退出逻辑。

## 并发与独立工具

`project-operations.mjs` 统一剧情项目 mutation lock、revision 和移动保护，不在领域内部另建事实锁。

`fact-storage.mjs` 只依赖 Node 内置模块，提供文件读写、路径检查和候选媒体锁；目标读据检查归 `edit-fingerprint.mjs`。`fact-commit.mjs` 在调用者持有的项目写锁内统一译文裁剪、引用检查、写入回滚及保存后的素材清理。译文文档规则位于 `page-translation-document.mjs`，不依赖译文保存或剧情编辑入口；领域调用者直接导入所需能力。

| 入口 | 条件 |
|---|---|
| `readFacts` | 一致性读取，期间变化有界重读 |
| `mutateTargetFacts` | 校验目标及必要依赖指纹 |
| `mutateFacts / deriveFromFacts` | 校验 expected revision |
| `mutateDerived` | 持锁但不要求或改变事实 revision；提交时冻结最新事实 |
| `copyProject / renameProject` | 校验源 revision，并协调生命周期 |

revision 是实时磁盘事实签名，不写项目 JSON；媒体和缓存不推进它，通知缓存不替代提交检查。浏览器只接纳当前项目及写入代次的快照，媒体独立刷新。

角色／场景的主保存与 Ctrl/Cmd+S 共用 `use-setting-editor`，仅提交当前基础页或子设定的当前模型；参考图先进入草稿。`setting-save.mjs` 在一次项目写锁内校验并提交档案、子设定 ID 连带引用与 Prompt，其他范围草稿保留。独立名称／描述字段可保守合并；同范围 Prompt 或必要基础依赖变化时丢弃过时草稿并提示，不拼接 Prompt、不自动重试写入。

真正的过时读据通过 `fact-conflict.mjs` 标记 `refresh_required`；浏览器据此作废排队的旧写入，普通业务 409 不触发刷新。`page-persistence.mjs` 和 `setting-persistence.mjs` 分别统一网页与 Agent 的归一化／校验；整页提交可以同步清理布局，局部内容提交仍拒绝破坏未授权范围的引用。落盘后的旧素材清理失败不改变保存成功状态；`saved-fact-receipt.mjs` 区分保存后的读取失败，返回 `saved:true` 和重读入口，不要求重复提交。

训练通过 TrainingOperations 和 ETag 协调，模块组合 facts、plan、runtime、media，不使用剧情锁／revision。对比工具独立冻结输入和成果，共用生成队列，不写来源页面；成品入口消费明确候选，不增加最终图扩散操作。

动态页后处理保存在页面 content，候选切换共用首尾裁剪与倍率；滑条和数值输入只改草稿，点击“应用”更新 WebP 预览，保存成功也同时应用参数。保存并输出共用此路径，保存失败不应用、不输出。总览与页内预览共用参数和 URL；默认仅加载最大宽度 320、质量 65 的 WebP；显式查看原图才请求原尺寸、质量 80 的 WebP，原图失败保留小图，就绪后可在灯箱内下载。动画只预热 320，静态图保留原策略。预览按来源文件和参数独立缓存，请求断开后释放共享编码消费者，最后一个消费者离开时终止子进程；后台预热也算消费者。`Saved/Logs/video-processing.jsonl` 记录编码 ID、来源、类型、参数、状态、错误和 `elapsed_ms`，以及缓存命中；`performance.jsonl` 的浏览器 `video-preview` 记录请求／解码阶段和耗时，用于区分预览失败与生成失败。成品冻结源字节与设置，生成原尺寸 WebP 和自适应无抖动 GIF，尺寸／帧率／颜色档位与 15,000,000 字节上限统一维护在 `app/shared/gif-policy.json`。每档从原片取样，达标即停，全部失败不发布；GIF 按最终播放时间轴取样，累计 10ms 舍入，不留下不超过 10ms 的短尾帧。两份均验证成功后发布，原始 MP4 仅作独立生产备份，封面采用裁剪首帧。source_video 保存原片时间轴，video 保存成品时间轴；备份缺失单独提示，不阻止发布文件导出。原候选不改写；设置变化使旧成品过时，处理失败保留旧成品。

WebP 预览按源字节哈希和档位共用完整原速缓存（`animation-v3-q65-q80`，URL 为 `video_v=3`）；冻结成品复用相同缓存，编码任务持有自己的源快照直到子进程退出，取消某个消费者不会删除其余请求依赖的输入。编码器追加 `SCVT` RIFF 块，以小端 uint32 帧数和 float64 fps 保存合并重复帧前的时间轴。旧版缓存首次访问重建，不改候选。裁剪按最近原片帧对齐，复用保留区间的压缩帧；起点依赖前画面时用 Sharp 重建完整边界帧并无损编码，若原边界帧清除子区域则继续重建到衔接稳定，完整独立帧可直接复用。仅改结尾无需解码画面。不同裁剪请求共用基础编码，派生文件取消后不发布。

单改倍率从同范围的原速 WebP 复制并修改 ANMF 帧时长，不启动 Python；按累计毫秒时间取整，始终从 1 倍速派生，避免多次变速累积误差。`video_preview_trim` 日志记录基础缓存等待、裁剪耗时和重建帧数；`video_preview_retime` 记录基础缓存等待和变速耗时。首次完整缓存缺失或档位变化仍需编码。最终 WebP 的 ANMF 时长不超过 10ms 时明确失败，避免浏览器拉长播放；GIF 片段不足 20ms 也明确失败，不静默改变速度。

成品导出支持高清、EH、Pixiv 和网页，四语言分别校验。高清混排原 PNG＋WebP；EH 混排 JPEG＋压缩 WebP，按章节优先拆独立 Store ZIP；Pixiv 仅静态 JPEG 按章节均分，GIF 单独目录，不补封面、不计入静态卷容量。限制维护在 `app/shared/finished-export-policy.json` 与 `pixiv-export-policy.json`；单 GIF 发布策略仍在 `gif-policy.json`。EH 与网页 MP4 从匹配哈希的冻结原片派生，保持裁剪和速度；旧 MP4 成品不重复后处理。派生仅写 Saved 缓存，所选版本缺页、过时或必需媒体缺失均拒绝。网页 HTML 内嵌静态 WebP 与 MP4，动画按可见性循环播放、离开暂停，无点击暂停及播放器控件；自动播放被拒绝时提供显式播放按钮。阅读工具栏默认折叠，轻点画面或页码展开，展开为单行，方向用单个开关切换，保留前后页、50%–300%缩放及键盘操作；点击缩放比例恢复适合屏幕，不提供输入跳转与操作说明，手机保留原生双指缩放。缺少 IntersectionObserver／ResizeObserver 时使用滚动与窗口尺寸事件，视口高度提供 vh 回退；这些处理不保证微信聊天附件预览器能够运行本地 HTML。发布提示与分包清单留在界面，不放进 ZIP。

本机批量导出先检查所有指定用途和语言，再顺序保存至项目 `Outputs/exports` 的独立目录，命名为范围-版本-用途-本地日期-时分，多项以 `_` 连接，重名追加序号。文件直接放在该目录中，复用动画缓存。每个文件先写.partial，再发布完整文件；取消保留已完成成果。HTTP 下载与本机保存复用同一流式媒体写出。网页界面的范围、用途、版本统一网格多选，默认全部不选；全文与具体章节互斥，多章按作品顺序合并、保留原页码，范围名称使用章节显示名称。浏览器下载与批量保存共用选择、分设按钮。浏览器按完整选择预检并准备全部文件后统一发放下载地址，逐文件启动原生下载并保留未开始文件的下载入口。导出全文时文件名范围使用“全文”。

无字版是已有成品干净底图的只读投影，不另建记录。跳过文字页并保留原页码，从中英日记录中优先选择原画依赖仍匹配且文件完整的底图；检查候选、分镜构图、组图原画来源和动态后处理，忽略译文、嵌字与后加素材。组图制作分别保存去除导入素材的 clean 和完整合成的 lettered；旧组图若含素材且没有独立无字来源指纹，禁止当作无字版导出，需要显式重制。其他旧成品无需迁移或重制。

网页导出先校验，再用 NDJSON 返回图片准备进度与最终分卷清单，通过十五分钟内有效的一次性地址交给浏览器下载管理器；取消准备会终止派生任务。网页不缓存 ZIP／HTML 字节或创建整包 Blob，下载进度与结果由浏览器显示。服务端提供准确 Content-Length，按背压流式传输，断开下载时停止读取文件；临时清单只存路径和元数据，不保存整包。

GIF 降级结果保存在成品 `gif.encoding`，界面显示为正常压缩说明。已有成品通过 `finished.gif.optimize` 显式检查与优化；只更新超限 GIF 及其元数据，复用冻结原片与后处理设置，校验记录指纹、源哈希和播放时长。WebP、原片、海报与原创建时间保持不变；旧 GIF 与记录在 Outputs/finished 的本次优化目录保留备份。合规文件不重编码，准备期间成品变化或正在制作时拒绝替换。

媒体缓存统一位于各项目 `Saved/media-cache/`，图片与视频按源字节、处理参数和编码版本复用；单份 `Saved/media-cache-index.json` 保存条目文件、大小和最近使用时间。服务本次启动后的首次缓存使用盘点现有文件，缺少使用记录的旧项视为冷缓存；之后只在新缓存发布后检查容量。每项目软上限 2 GiB，超限标记待办，项目没有缓存使用者时按最近使用时间回收到约 1.5 GiB，不设置定时巡检。读取命中只更新使用时间，累计 64 次或新增缓存时合并保存索引。媒体响应、后台预热、共享编码、成品处理和导出全程持有项目级使用保护；下载票据持有至消费后传输结束或十五分钟过期，忙碌时允许暂时超限。GIF／动画及其元数据成组回收，仅删除已发布的普通缓存文件，不扫描成果、任务记录或 staging；缓存缺失按需重建，维护失败不改变已完成任务结果。

静态成品底图在同页内按内容共享，各语言嵌字媒体独立保存；底图路径见 `finished-page.schema.json`。发布共享文件、切换记录和旧媒体引用检查都在项目写锁内执行；替换、删除和失败清理只回收本页三语言记录已无引用的媒体。页面归档沿用整个页面成果目录，不跨页共享。已有成品不在读取时迁移，显式归并经 `finished.clean.inspect/share` 校验记录与底图字节，先保存共享像素再事务切换引用，最后清理旧副本；不改变其他字段及创建时间。

## 生成资产与冻结

| 资产 | 维护内容 |
|---|---|
| `library/render-profiles/` | 模型身份、模型 Prompt 配置、LoRA、operation 和输入 route |
| `library/render-recipes/` | 采样与画幅 |
| workflow API 模板及 manifest | 可执行节点、operation、输入、modifier 和节点绑定 |
| 项目 override | 稀疏稳定 target、基础值和项目值 |
| 页面 render | 独立模型、profile、画幅，创建后不继承默认变更 |

字段以 Schema 和资产为准。profile 直接组合、不使用 extends；绑定只在 manifest；route 必须显式声明。modifier 只变换已选 workflow，语义 ID 冲突报错。override 不存全量副本，保留基础值判断冲突。

`page-render-resolver.mjs` 读取最新事实，模型与 `render-profile-compiler.mjs` 编译；`render-task-contract.mjs` 冻结配置、来源、文件、Prompt、LoRA、seed、route 和执行单元。入队前实例化 workflow 及输入输出映射，`render-project-runtime.mjs` 只消费 task ID 对应快照，恢复不重读当前页面或配置。

契约错误、输入身份变化或启用资源缺失阻止执行，不静默跳过或换路线；恢复失败进入明确终态。候选由 `render-media.mjs` descriptor 定义身份与映射，并验证成果完整性。

## 模型接入

服务端在 `model-adapters.mjs` 显式注册 `models/<model>/adapter.mjs`。适配器维护原生输入创建、草稿预览归一化、角色／场景设定解析、设定基础字段及依赖、编辑辅助、校验与编译；公共模块不把未知模型当作 Qwen。`model-prompts.mjs / prompt-scope.mjs` 管容器、引用及范围保存，继续共用事实锁和读据。

前端在 `app/src/models/registry.tsx` 注册各模型的 `ui-adapter`；适配器组合专用页面、总览和设定编辑器，并维护原生初始化和校验。宿主负责草稿、保存、导航及共用操作，编辑器只修改宿主草稿。原生输入类型放在各模型目录，不增加持久化类型标记或通用表单生成器。

专有能力按实际使用归属模型，不预先统一 Anima 词条、Qwen 参考图或未来模型的空间输入。纯框架整理保持项目格式、继承行为与生成默认值；冻结任务的 Prompt 契约身份单独维护，不根据注册表顺序重算。

新增模型沿现有注册路径，不另建插件加载器；修改 workflow／recipe 同步 Schema、引用、编译和冻结测试。参考图、LoRA 或采样变化须核验真实冻结工作流及输出映射。模型专有知识见[Qwen](../reference/qwen.md)，字段语义查 prompt 操作 topics。
