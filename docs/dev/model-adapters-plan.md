# 多模型工作台实施计划

状态：本轮实现与核心功能验收已完成（2026-09-25）。基线为 `653d1fe`，开发分支为 `codex/model-adapters`。
本文保留本轮目标、顺序和验收证据；当前操作契约以 [模型适配器](model-adapters.md) 为准。

## 1. 已确认的产品边界

- 保持独立应用、一个 Node 服务、原 React 工作台和项目文件存储。
- Anima Basic 是主要创作路线，只恢复 `anima-base-v1`，不恢复 Aesthetic。
- Qwen-Image-2.1 是可在单页使用的补充生成路线；不引入候选图片修改、后处理链或云端 NAI 实现。
- 页面可以独立选择生成配置和画幅；项目默认值仅在创建时复制。更改默认值不改变已有页面。
- 切换模型保留各模型的页面 Prompt；不将整个项目切换成另一套创作流程。
- 保留 Anima 词条编辑器、逐词继承、分类、人数与机位编辑；保留现有候选、预览、快捷键和工作台布局。
- 保留 Qwen 最近实现的 ComfyUI INT8 PE-T2I 提示词优化、原文/优化稿选择及过期检查。
- 本轮不改训练配置、训练器、训练 UI 或已有训练项目；现有对比实验和成品功能继续工作。
- 正式旧项目仅迁移爱经；允许创建临时项目进行验收。不得修改爱经原文、剧情或 Prompt 内容。

当前 Qwen 与候选功能以 `653d1fe` 为准。不能整体回滚 Qwen 改动或覆盖共享文件。

| 内容 | 做法 |

| CameraControlDialog、PromptPopulationEditor 及相关 CSS、draft/helper | 恢复原实现，保留键盘、浮层与输入法处理 |
| prompt-tags、prompt-inheritance、camera-prompt、inline-prompt-weight | 恢复纯逻辑及对应行为测试，放在 Anima 所有权下 |

## 3. 最小内部插件边界

采用代码内显式注册，不引入动态安装、依赖注入框架、运行时卸载、通用表单 DSL 或第二个服务。

```text
页面/候选/排队/进度/媒体/成品（公共工作台）
                │
       页面生成设置 + 模型适配器注册表
                │
       ┌────────┴────────┐
   Anima 适配器        Qwen 适配器
   词条和继承          自由文本和提示词优化
       └────────┬────────┘
         冻结生成输入/执行计划
                │
       ComfyUI 执行器与公共候选发布
```

服务端适配器拥有：模型专用 Prompt 的校验/空值/编译、来源依赖、参考图能力、生成参数与工作流装配。
前端适配器拥有：页面 Prompt、设定 Prompt、模型设置及生成详情的模型区域。
公共外壳拥有：保存/离开保护、PageKey、画幅和模型选择、候选浏览/删除、进度、任务生命周期。
外壳通过显式组件 props 和普通函数连接，不接管词条内容或自由文本拼接规则。

后端注册和前端注册分开，使用同一稳定模型 ID（`anima`、`qwen`），profile 决定模型适配器。
模型 ID 和 profile ID 不混用。公共投影提供能力描述，由 UI 决定是否展示参考图和提示词优化。
模型详情保存在冻结任务/候选中；历史候选使用自身模型、尺寸、Prompt 和设置，不能按当前页模型解释。
未来 NAI 需要新适配器和执行器；本轮仅确保候选发布接受普通图片结果及模型详情，不预建 NAI 参数与鉴权。

## 4. 页面事实和默认值

目标契约将页面生成设置放在独立 `pages/<id>.render.json`：

```json
{
  "version": 1,
  "profile_id": "anima-base-v1",
  "canvas": "2:3"
}
```

生成设置不是 index 的归属信息，也不是页面正文。初版沿用已存在的画幅选项和对应模型的尺寸配方；
模型不支持某画幅时明确报错，不能静默换画幅。文字页同样使用本页画幅。
项目 `canvas`、`default_render_profile` 保留为新页默认值。创建一次复制，复制页面复制原页值。
已有页迁移时一次性填入旧项目有效值；读取时不能长期靠项目默认值兜底形成隐式继承。

模型专用页面输入共存于页面 Prompt 文档的模型空间，公共页面只选择当前模型输入。
实现时优先使用单一、明确的模型输入容器，禁止同时维护两份“当前 Prompt”事实：

```json
{
  "models": {
    "anima": { "subject": [], "person": [], "setting": [], "camera": [], "avoid": [] },
    "qwen": { "text": "从有效 Anima Prompt 一次带入的文字" }
  }
}
```

示例中的 Anima 数组仅表示模型所有权，内部字段必须沿用历史 schema 的完整结构，不简化继承与角色绑定。
只有实际使用过的模型才需要输入。角色/场景同样让适配器拥有其 Prompt 结构；已有 Qwen 设定与引用不丢失。
公共 read/save 负责目标指纹、依赖指纹和提交，适配器校验自身数据。公共层不得把模型输入转换成另一模型的格式。
保存、复制、删除归档、项目复制、revision 扫描、Agent read/save、材料引用扫描必须一起覆盖新事实。
角色/场景子设定重命名和删除必须遍历所有已存在模型输入，包含非活动模型的 scene、inheritance、
text/reference overrides 和材料引用；不能只修改当前 UI 投影。
切模型涉及新增输入时与 render 选择一起原子提交；离开前沿用现有未保存草稿处理。

## 5. Qwen 的具体体验

Anima 页面第一次选择 Qwen 时，将当时 Anima **完整有效正向 Prompt** 一次带入 Qwen 本页输入，
不只拿本页手写片段，不丢全局、角色、场景和逐词 override 的实际效果。负向保留在 Anima；
Qwen 编译仍保持其自身契约，不伪造负向能力。
之后 Anima 修改不自动覆盖 Qwen 草稿。提供明确的“重新从 Anima 带入”，有 Qwen 未保存编辑时沿用冲突/离开保护。
Qwen 不要求在 Anima 项目中再维护一套角色、场景 Prompt；已存在的纯 Qwen 项目保留原设定编译能力。
Qwen 输入显式记录 `composition: "standalone" | "settings"`：Anima 带入使用 standalone，
文本已经完整，不再追加全局/角色/场景文字，也不默认引用其图片；已有 Qwen 的 settings 组合方式，
保留原确定性拼接和参考图语义。两种模式的依赖和输入来源明确，不能通过有没有设定数据来猜测。

参考图通过已有候选选择入口引入。持久保存时复用现有材料提升逻辑，复制至项目 `materials/`，
存储稳定材料引用和用途。删除源候选或切换当前模型后参考仍可用。不得直接持久引用可删除的 Outputs 路径。

PE-T2I 优化是 Qwen 专属能力：

- 保留 ComfyUI runner、INT8 配置、生成/显示优化稿、原文或优化稿生成选项。
- 过期指纹绑定 Qwen 输入、实际页面画幅、参考图及模型身份；更改这些条件后显示过期提示，仍允许显式选用旧优化稿。
- `wh_ratio` 是建议，不能自动修改页面画幅。
- 完成优化后的迟到结果仍检查源和目标指纹；切换模型期间不能覆盖另一份输入。
- 任务提交冻结实际选择的文本，排队以后修改页面不影响已提交任务。
- 优化稿随 Qwen 输入保留；切回 Anima 不清空它，也不显示为 Anima 能力。

## 6. LoRA（仅推理）

项目 LoRA 对使用对应配置的页面实时生效；模型之间不共用不兼容 LoRA。
页面模型输入各自保存追加与覆盖列表；新页和新增模型输入不复制项目列表。
普通页面只显示启用、权重、移除和添加；种类标签只帮助查找，不影响执行优先级。
项目和本页按文件名合并，本页的权重与停用设置优先；不隐式叠加角色、场景 LoRA。触发词来自合并后的启用列表，并参与 Anima 编译。
迁移把旧页面的**有效列表**按顺序展开，保留权重及身份，不自行增加、替换或删除任何 LoRA。
旧 Anima 风格 LoRA 的自动触发词也属于有效 Prompt：迁移将其明确保存在 Anima 输入中，
按历史顺序参与编译，不因取消隐式 LoRA 层叠而丢词或重复注入。新添加 LoRA 不自动改写 Prompt。
不迁移或改变训练系统；全局资源可用性与兼容筛选复用现有实现。

## 7. 生成、候选与配置衔接

所有入口（单页、总览批量、Agent、检查、实验导入）调用同一个页面有效生成设置解析。
页面 profile 不等于项目默认 profile 时，不能误套另一 profile 的稀疏项目 override；
已有 override 的有效值由迁移/默认复制明确保留，模型参数应由自身设置编辑器负责。
先冻结模型、输入、画幅、尺寸、LoRA、参考图、配置身份，再建立任务。
执行器只读取冻结任务；保留当前队列、取消、重启恢复和原子候选发布机制。
候选公共信息为 PageKey、任务/候选 ID、图片与尺寸、时间、seed、模型标识和生成条件签名；
模型细节与执行计划分离，不把 ComfyUI 节点结构暴露给候选工作区。
生成条件签名比较真实条件，换模型或画幅会失配，切回原条件可重新匹配旧候选。
旧候选照常浏览，不能为迁移而删除候选或伪造新模型元数据。

## 9. 分阶段实施与验收

| 阶段 | 交付与范围 | 放行依据 |
|---|---|---|
| A：计划与基线 | 详细文档、subagent 审查、测试基线、历史文件清单 | 审查意见逐条处理；无未解决的结构性阻碍 |
| B：适配器与事实边界 | 模型注册、Prompt 所有权、页面 render、创建复制保存和迁移 dry-run；先保住 Qwen | 类型检查；事实冲突/默认复制/模型切换/原 Qwen 编译/复制归档测试 |
| C：Anima 恢复 | Basic 资源、历史词条与继承编译、原页面与设定 UI、简单 LoRA | 临时项目 Anima 编辑与检查；历史键盘/IME/拖动/继承浏览器用例；模型切换输入保留 |
| D：Qwen 与公共生成 | Anima 一次带入、候选参考、PE-T2I 保留、统一单页与批量条件、详情适配 | Qwen 回归；优化稿 stale/晚到/原文选择/冻结测试；跨模型候选与画幅测试 |

阶段内允许为闭环调整提交顺序，但不能将未接线的适配器当作完成，也不能先迁移正式数据再修 UI。

1. 项目默认 A/2:3 创建页一；改默认 Q/4:3 创建页二；页一仍为 A/2:3。

7. 同页两模型/两画幅生成结果共存，画廊尺寸/详情正确；重启任务恢复与生成条件匹配保持。
