# Qwen-Image-2.1 接入

生成设置可选择 `qwen-image-2-1`，保留 Anima 配置供已有项目使用。默认约 1MP、25 步、
Euler / simple、CFG 1；沿用原有候选任务、逐张队列、种子、输出与历史记录。

## 页面输入

角色／场景的每个子设定维护有序 `reference_images: [{ id, file, title }]`。
剧情页引用该设定后自动使用首张图，展开 Prompt 的角色／场景行后可以停用、选多张或恢复默认。
页面 `reference_overrides` 用 `character:<id>:<variant>` / `scene:<id>:<variant>` 映射选中的条目 ID；
缺省跟随首张，空数组停用，显式列表固定选择。页面 `reference_images` 保存本页附加图片。
图片按人物顺序、场景、本页附加图片的顺序输入，合计最多 10 张；超限明确阻断，不静默截断。
设定页在子设定内独立展示参考图。“＋”打开当前子设定的候选选择面板，可跨候选页多选并一次确认；图片依次保存，中途失败保留已完成项，重试只处理剩余选择。候选提升后复制为独立素材，不受候选清理影响。缩略图点击复用全屏看图器；右键（触屏长按）提供替换与移除。右上角六点手柄用于拖拽排序，桌面悬停显示、触屏常显，首张标记为默认；替换保留引用 ID，移除与替换后清理不再使用的旧素材。设定页与剧情页共用小号“＋”和选图面板：设定页默认列出当前子设定的候选图，剧情页默认列出项目已有 PNG/JPEG/WebP 图片。面板首项“＋”展开选择文件入口，也可直接拖入图片；预览、填写名称后确认上传，单张上限 32MB，取消不保存。

没有生效图片走文生图，有图走参考图路由。角色／场景／参考图选择与继承词只出现在 Prompt 区域。角色、场景标题行直接显示可操作标签，统一通过“＋”搜索选择、标签内切换子设定和叉号移除；角色多选、场景单选。展开后显示参考图与继承词，继承词直接展示，不再提供独立折叠标题，各设定用边框分隔，角色排序沿用拖拽。参考图点击切换，原色表示启用、灰色表示未启用，不显示标题或勾选框。Prompt 最下方按实际输入顺序汇总全部启用图片：继承图片只读，本页附图带小角标，可右键替换／移除、拖拽排序和点击看大图。末尾“＋”选择项目已有图片或上传，保存为本页独立素材，不改动来源设定。剧情页附图与内容、Prompt 共用本页草稿，添加、替换、移除与排序都随整页保存或放弃；上传内容暂存在浏览器，保存时才复制／转换图片，失败清理本次新文件并保留原图，成功后清理失去引用的旧图。设定页仍即时保存；添加按当前生效引用计算剩余容量。

角色／场景设定中的参考图管理支持从候选中选择、排序、替换和移除。图片转换为 PNG，统一保存到项目
`materials/reference-<uuid>.png`，纳入项目 Git；候选清理不影响它。
替换保留条目 ID，手动引用也跟随最新版本。先准备新文件，成功保存事实后删除不再使用的旧文件；
排序只影响默认引用，手动选择不变。删除手动引用中的条目会列出页面并拒绝，需先取消或恢复默认。
删除子设定／设定／页面时同时清理不再使用的受管参考图；导入前的原始材料不自动删除。
设定页写入通过 `/workbench/reference-library` 的 `read/save/reorder/delete` action 与列表指纹完成；剧情页通过 `/workbench/page-save` 同时提交 Prompt 条目与临时 `reference_inputs` 图片来源，图片来源不写入事实文件。
复用事实锁和草稿保存，冲突不覆盖；冻结任务已有的输入文件不受当前参考图替换影响。
参考图删除检查与旧素材清理由统一事实提交处理，网页和 Agent read/save 一致；仍被页面手动引用的设定图不能删除，旧文件已缺失时仍清理素材索引。

输出尺寸始终取项目画布配方，参考图尺寸不改变画布。

保留结构化 Prompt、角色/场景继承和机位控制。Qwen 的 `positive_avoid` 策略
把有效负向文本追加为正向末尾的 `AVOID: ...`，传给节点的负向输入为空。负向片段仍保留原始
来源与审计记录；流程预览中的最终文本包含转换结果。这只是自然语言提示，不等同于 CFG 负向引导。

首版不支持 Qwen LoRA，以及把带参考图页面导入对比实验；这些情况明确报错。
已有 Anima LoRA 不会在切换模型后被静默忽略或套到 Qwen。

## 冻结与目录

- 正式权重及配套文件位于外部 `models_root/diffusion_models/`、`text_encoders/`、`vae/`；
  模型精确文件名、大小、SHA-256 与来源在 `library/render-profiles/qwen-image-2-1.json`。
- Prompt 策略、配方和两个工作流分别位于 `library/prompt-policies/`、`render-recipes/`、`workflows/`。
- 原始参考图是项目材料。创建任务时读取一次，按 EXIF 转正、最长边限制 1536 并转成 PNG；
  源文件与标准化图片分别记录 SHA-256，图片原子写入任务目录 `inputs/<sha256>.png`。
- 运行时只读取冻结图片并复核 SHA-256，通过 HTTP 上传至执行端 ComfyUI 的
  `input/StoryCanvas/references/<sha256>.png`；同一任务按内容 SHA 去重上传。本机和远程共用此路线。
- 任务归档时图片随任务进入历史目录；候选仍存于项目 `Outputs/pages/`。临时脚本与检查结果位于根
  `Saved/Agent/qwen-integration/`，不作为正式生成依赖。

## 官方基础与验证

以 [官方文生图模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_t2i.json)
和 [官方参考图模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_image_edit.json)
为基础，使用 `TextEncodeQwenImage21`，参考图路由保留 `QwenImage21Cache`。工作台冻结自己的 API JSON，
无需用户编辑 ComfyUI 图。模型来自 [Comfy-Org 发布目录](https://huggingface.co/Comfy-Org/Qwen-Image-2.1/tree/main)。

2026-09-21 在 ComfyUI 0.37.0、RTX 4090 24GB 上通过正式工作台接口生成两页各三张：
文生图整组约 20 秒，单参考图整组约 28 秒（含队列、上传、下载和落盘；不能视作其他设备的保证）。
六张均为 832×1248。参考图组保持了发型、头饰和服装大体特征，小配件不保证精确复现。

自动化覆盖 AVOID 的任务冻结与复验、参考图路由、排队后材料替换、损坏检测、不支持配置阻断，
以及浏览器中的选择、保存和移除；Anima 使用原有回归测试。

候选匹配使用最终正负向、实际模型 SHA-256、LoRA SHA-256／权重／加载顺序、参考图规范化内容与输入顺序、当前画布尺寸、采样参数及工作流身份。种子和显示名称不参与匹配。两步深度生成实验已移除，页面只保留一次生成候选的路径。

2026-09-21 多参考图首版端到端验证：工作台选取原参考图与一张既有候选，真实排队三张 832×1248 图片，全部成功。整组约 178 秒，首张约 150 秒，后两张约 17／11 秒；ComfyUI 日志显示三张等待时间约 0.04／0.02／0.02 秒，实际执行约 149.5／15.6／10.4 秒，首张额外耗时发生在执行内，具体节点原因未在本轮隔离，不作为稳定吞吐基准。三张均保留，角色外观大体一致，配件有差异。十张输入的顺序、冻结与工作流连接已通过自动化验证，未做十张图片的 GPU 压力测试。
