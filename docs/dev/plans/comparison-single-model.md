# 单模型对比实验完善方案

状态：已完成方案审阅、实现、回归及独立代码审阅；本机工作台已更新。未启动正式训练或真实生图。

## 范围与结果

本轮完善工作台内的同模型对比：原生输入、实际画幅、明确的 LoRA 替换与基线、训练与生成底座兼容性。保留现有实验列表、输入卡片、参数扫描、结果网格、灯箱、队列及失败重试。跨模型继续使用独立实验；Agent 可通过已有 review / diff / sheet 接口汇总结果或编写展示网页。本轮不新增跨实验对照 UI、测试用例库或统一执行矩阵，不启动用户正式训练。

实施顺序：方案审阅 → 按边界开发 → 集成与验证 → 独立代码审阅 → 修正并部署。未经另行要求不提交 Git。

## 已确认的问题

1. 对比输入只有最终正负文本；MOSS Layout 已编译成 JSON，角色 LoRA 替换继续按逗号、换行删词并在末尾追加，可能损坏 JSON 或误处理角色描述。
2. 页面导入没有保存实际 candidate_recipe，分镜尺寸或页面尺寸倍率可能丢失；改变画幅时旧绝对坐标不重新计算。
3. 测试 LoRA 默认追加，替换仅针对角色。页面带着旧 Veloria 时，再加入新 checkpoint 会意外叠加；“基线”也不等于移除 Veloria。
4. 正式 LoRA 的训练底座 SHA 被作为生成底座的严格一致条件，BF16 训练／INT8 生成会被误挡。裸权重不应成为绕过检查的入口。
5. 全局扫描轴为笛卡尔积，混合模型与各家的 LoRA、CFG 无法合理配对。

## 输入与编译

- 新建实验必须只有一个生成模型家族，界面和服务端均校验；同家族内各输入仍保留各自配方。默认 CFG 沿用输入配方，只有用户填写扫描值时覆盖。
- 导入冻结实际候选 recipe、所选 route、最终尺寸依据、模型、LoRA 和参考图，保持来源页面不变。分镜或倍率改变后的实际尺寸不能退回全局默认。
- MOSS 输入新增显式版本的原生快照，保存页面描述、已解析的角色／场景描述、稳定角色 ID、归一化 Layout 和触发词归属。复用正式编译器，在每格 LoRA 与最终尺寸确定后再生成文本；最终文本是预览和执行证据，不是原生快照之外的第二份可写事实。
- MOSS 空白输入也使用同一原生结构。界面提供自然语言编辑，Layout 复用已有弹窗；模型专有编辑放在 MOSS 目录，不增加通用原生表单框架。
- Anima／Qwen 普通文本沿用现有编辑器。无归属信息的文本不允许猜测触发词属于哪个角色；需要自动替换时必须有确定的匹配依据，无法确定时返回可操作错误，不静默改全文。
- 新 manifest 使用 v2，preflight 使用 v3，原生快照及输入有明确版本；旧版本使用固定历史验证规则。execution 结构不变时沿用 v1。已有实验及冻结工作流不重写、不读取新来源替换旧输入；已生成历史继续可查看、导出，已有 execution 按原冻结内容重试。未生成的旧输入不得在新版编译语义下悄悄重新解释，明确要求重新导入创建，界面停用旧实验的启动操作。
- MOSS 空白输入允许添加本地人物描述与稳定 ID，供 Layout 使用；它们只是实验输入，不创建项目设定。引用多个人物的同一权重保留所有触发词归属。

## LoRA 操作与基线

- 保留“额外叠加”，新增“替换指定 LoRA”，目标通过冻结输入中明确的文件身份匹配，支持画风、角色及普通附加 LoRA。多输入必须能唯一匹配同一目标，缺失或歧义在创建前阻止。
- 替换只移除选中目标，保留其余 LoRA。一个正式资源文件在结果中只能按明确规则加载一次，避免原输入和新增测试权重重复。
- 替换模式的空测试项命名为“移除该 LoRA”；追加模式命名为“原输入 LoRA”，不能统称完全无 LoRA。原方案可作为实际候选加入，不隐含成另一个基线。
- 每格展示实际加载的 LoRA、权重和最终 Prompt。自动触发词处理跟随已确认的归属，保留其他角色的同名文本；没有新增资源触发词时不猜测。Prompt 发生变化时如实显示，不声称只改变了权重。
- 原 replace_character 冻结历史按旧契约读取；新建界面统一用明确文件目标，参数及兼容行为同步到 CLI help 和 Schema。
- 目标用 SHA 精确匹配，文件名用于展示；多输入中每次只能匹配一份。同文件不同路径也不能追加重复加载。
- 触发词策略显式为 `preserve`（默认，保持原 Prompt，只改变挂载／权重）或 `replace`（同步目标触发词）。移除基线也遵循同一策略。这样无需归属信息的普通文本仍可进行纯权重对比；要求同步时才检查唯一归属。裸 checkpoint 的 activation 未知与明确空数组分别处理，未知时不得自动删除原触发词，可保持 Prompt 或由 Agent 显式提供触发词。

## 模型兼容与文件身份

- 架构家族不一致始终阻止，文件 SHA 和大小仍用于冻结与启动前完整性校验。
- 训练底座身份如实保留；生成兼容关系单独声明。只维护当前确有依据的精确模型身份关系，首个必要关系为 MOSS SFT BF16 DiT 与本机 SFT INT8 ConvRot DiT。不能把所有同家族或所有 Base/SFT 自动当作兼容。
- 非 DiT 的编码器／VAE 训练来源不自动变成纯 DiT LoRA 的加载约束；检查以已知适配目标为依据。未知目标或不匹配身份给出明确诊断，不改写来源身份、不靠裸文件绕过。
- 兼容性判定需进入冻结预检证据，开始运行时复核实际目标与 LoRA 文件身份。历史冻结内容不会因后来新增兼容关系而被改写。
- 关系是单向、非传递的可加载声明，不代表成图质量等价。SHA 复核覆盖输入原有和测试 LoRA。已登记社区资源的来源不完整应报告“身份不足”，不能误报“架构不兼容”；本轮不自动迁移或改写资源登记。

## 页面与工具接口

- 现有新建表单明确当前模型，只接纳同模型输入。导入当前页面模型时明确显示实际模型，混入其他模型拒绝并说明；本轮不新增跨模型分支转换。
- 输入卡片显示实际尺寸。MOSS 使用模型专用描述编辑和 Layout 弹窗；普通模型保持原文本编辑。扫描条件继续使用已有区域。
- LoRA 应用区明确选择“追加／替换”及目标。创建前列出图片数量、实际基线含义；预检 errors 在此显示，不到运行中才发现。
- Agent 使用 blank / import 获得结构化模板，编辑副本后 create；增加必要的只读输入／计划预览能力，让 Agent 和网页都能检查原生编译结果。具体字段和副作用由工具 help 与 Schema 维护。
- review / diff / sheet 保留跨实验能力，只消费已有结果。本轮不新增跨实验显示控件。

## 验证与交付

必要回归：

1. 混合家族新建拒绝，同模型不同输入与默认配方正常；错误不会写入半成品实验。
2. MOSS 开／关 Layout 均能替换目标角色，另一角色不受影响；替换风格 LoRA、移除目标基线、保留其他 LoRA，无重复挂载。
3. 正常画幅、页面倍率、分镜实际尺寸导入保持；改画幅后框选坐标重新编译且仍引用同一人物描述。
4. BF16 → 已声明 INT8 兼容通过，其他未知 SHA／跨家族拒绝，文件变化在启动前阻止。
5. 创建后改来源页面、模型默认值或其他项目事实，不改变冻结执行；旧历史可查看、已有冻结执行可复核，不隐式升级。
6. 浏览器覆盖模型限制、替换目标、基线文案、MOSS 描述与 Layout 编辑、错误反馈、重复创建及草稿保持。
7. 最终类型检查、构建、后端完整测试、相关浏览器测试；利用隔离夹具验证真实工作流节点及冻结输入。必要的真实接口验证只做只读预览，不启动昂贵生成。

交付当前实现、审阅结论、验证结果与已知限制；完成后更新本机工作台。真实项目素材、页面和旧实验不在本轮直接改写范围。

## 实施与验收记录

- 原生输入与正式编译器共用，预览和执行共用逐格编译入口；新输入 v1、manifest v2、preflight v3，execution 延续 v1。
- 只支持同模型家族的新实验；已有跨实验 review / diff / sheet 继续使用冻结结果。
- 独立审阅发现的触发词与分类标签混用、基础 LoRA 删除后的归属残留、冻结执行详情缺失、创建响应丢失后的重复提交及 inspect 证据遗漏均已修复，并经过审阅者复核。
- 类型检查与生产构建通过。完整后端回归 1040 项通过、1 项跳过；审阅修正后的对比实验与 Agent 接口回归 127 项通过；浏览器回归 18 项通过。
- 本机正式 Agent 接口完成空白 MOSS 原生输入和 Layout 只读预览：画幅 1280×960，归一化框正确编译为绝对坐标，未创建实验、未调用 GPU。
- 旧实验保留查看和导出；只有已有冻结 execution 的旧实验能继续重试。底座身份不完整的 LoRA 需补充来源声明，不能以未知来源冒充已验证兼容；本轮不自动改写资源事实。
