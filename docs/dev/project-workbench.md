# 项目工作台

## 按当前视图载入

浏览器 `GET /api/projects/:id/workbench` 默认只返回目录摘要；`scope` 查询参数是 JSON，
支持 `directory`、`page`（`page_id`）、`setting`（`setting_kind`、`setting_id`）、
`story`（可选 `chapter_id` 或 `sequence_id`）、`prompts`、`lettering`。
同一事实快照只组织目录与当前视图的数据。页面详情仅在其归属目录中出现，不再额外传输顶层
完整 `pages` 副本；未读取的 Prompt、编辑指纹和生成能力不填空值冒充已读取事实。

目录仍从各页 content 文件提取标题，不在页面索引中重复持久化标题；不读取页面 Prompt、
render 或编辑依赖，也不编译生成配置。正文总览只读取当前章节／单元的展示内容，全文总览
读取全文正文。Prompt 总览在打开时读取剧情页 Prompt 与保存依据，不预编译每页生成配置。
当前单页读取自身编辑事实和已引用的设定；草稿新增引用通过 `workbench/setting-detail`
补读。未读完或读取失败时不能保存；来源版本仍按编辑时的读据保护。

切换范围和后台同步共用快照接纳流程，迟到的旧范围响应不推进项目写入版本。当前视图载入
前只显示目录和载入状态；同范围后台刷新保留编辑器及未保存草稿。结构变化导致当前页删除
时先按目录选择回退页，再读取该页详情。

Agent 的嵌字读取使用 `GET workbench/lettering-settings` 和
`GET workbench/page-lettering?page_id=...`，只返回对应内容及 `expected_sha256`。
成品列表和单页成品操作仅组织正文、布局及文字页尺寸，不读取生成 Prompt。

候选媒体位于 `Outputs/pages/`，`w=320`／`w=1024` 返回磁盘缓存的 WebP，候选路径按不可变
私有资源长期缓存；其他可变素材不因此启用长期缓存。生成失败仍可回退原图。

浏览器通过普通项目 URL 打开唯一工作台：

```text
http://127.0.0.1:3000/?project=<project-id>&tab=story
```

前端共用项目切换、章节/sequence/页面与角色层级导航、候选区和项目数据。
项目在磁盘上的文件组织只属于服务端实现，不成为用户入口或项目类型。

## 导航与页面生成

普通切换项目进入「项目」管理页，不记各项目上次位置；复制或重命名后进入目标项目也使用这一入口。
浏览器刷新按当前 URL 恢复标签、页面或角色子设定，从任务详情跳转直接打开对应项目页面。
离开有未保存修改的编辑区仍先提示，取消离开时保留草稿与当前位置。
同一角色设定的各子设定共用草稿，内部切换保留修改、不提示放弃；离开该角色编辑器时仍提示。

左侧固定分区为「设定、系列、输出、工具」，切换分区只改变目录，实际打开内容才切换工作区。
设定内部保留角色与场景分组。目录默认收起内部内容，按项目记住折叠；定位时展开目标路径，保留其他分支。
页面无折叠箭头或其空占位，剧情页显示全系列连续页码，角色视觉页按各子设定从 01 编号。
新增入口统一在标题／条目的右键菜单（触屏长按），同级新增插在当前项之后，下级新增追加到容器末尾。
六点柄单独负责拖动排序。候选图数量仍显示在页面右侧，不代表验收或成品状态。

顶部后退／前进只记录本会话当前项目内打开过的内容，包括场景、章节／单元总览与页面编辑标签；
取消离开不改变历史位置，刷新或切项目清空记录。顶部搜索支持当前项目的页面、角色、子设定、视觉页与场景，
纯数字定位全系列剧情页码。搜索和历史跳转都同步左侧分区与当前项，不保存跨页草稿。

导航树只打开单个页面，不提供 Ctrl／Shift 页面多选；页面编辑区的生成操作只提交当前页，
仍可选择生成 1 或 3 张候选。Prompt 总览批量排队、剧情总览候选操作和候选图片多选保持独立。
当前页被删除时，优先打开原组中仍存在的后一页，否则前一页；剧情按 sequence、角色视觉页按
角色与子设定限定范围。原组没有剩余页面时显示空态。菜单删除与后台刷新共用此规则。

## 剧情总览候选刷新

分页卡片采用顶部对齐的纵向布局，缩略图区域固定为 3:4，按最新生成时间展示候选。仅屏幕内
卡片串行刷新自己的媒体；点击缩略图打开可缩放的全屏预览，点击标题进入对应页面。标题行
右侧提供“+”，直接按已保存事实提交单张普通生成任务，提交期间禁用按钮。

剧情总览提供“清理候选”和“生成候选”，操作收在阅读栏“更多”中，范围为当前全文、章节或情节单元，不含角色视觉页；弹窗显示范围名称，页码保持全故事编号。
清理可选“清理不符候选”（默认）或“清理全部候选”；生成可选“缺失候选的页面”（默认）或
“所有页面”，并选择每页生成 1、2、3 张（默认 1 张）。缺失指没有与当前生成条件相符的候选。
匹配规则沿用单页：比较最终正负向文本、模型 SHA-256、LoRA SHA-256／权重／顺序、参考图内容、当前尺寸、采样参数和工作流身份；不比较种子与显示名称。
两个操作先扫描，再通过可滚动的确认清单显示页面序号、标题及删除／保留数量；无法编译或已有
活动生成任务的页面跳过，只列标题；清理全部不依赖 Prompt 编译，可清理无法编译页面的候选。
清理不可撤销；生成按指定范围和每页张数，按剧情
顺序进入普通生成队列，不增加批次历史或结束后的失败页汇总。

`POST /api/projects/:id/workbench/story-candidate-refresh` 的 `inspect` 请求每批最多接受 8 个
`page_keys`，服务端最多并发编译 3 页，只返回匹配数量、签名及不符候选 ID，不载入候选详情。
浏览器分批扫描并显示进度，可取消扫描。确认后逐页提交 `clean`／`generate`，在现有
`mutateDerived` 边界内重查 Prompt、候选和活动任务；除清理全部外，签名变化拒绝执行。清理
请求的 `scope` 为 `mismatch`／`all`，删除只取确认 ID 与当前对应范围 ID 的交集；生成的
`scope` 为 `missing`／`all`，`count` 为每页张数。缺失模式跳过已经有相符候选的页面，所有模式
仍跳过活动任务页面。提交期间可以停止后续提交；离开
总览也停止后续提交，已提交任务仍由现有队列执行。生成结果与错误沿用普通页面任务反馈。

## 宽度层级

工作台只有完整功能一种模式；视口宽度只改变布局层级，不裁剪能力。判断集中在
`app/src/workbench-presentation.ts`，不按设备型号或 User-Agent 判断；手机请求桌面版
通常提供更宽视口，但具体行为以浏览器为准。

目录是否收进抽屉按 1160px 判定（`NAVIGATION_DRAWER_MEDIA_QUERY`，含窄桌面窗口与手机
请求桌面版的约 980px 视口）：不超过时不渲染常驻侧栏，目录由顶栏按钮以抽屉打开，编辑与
生成能力不受影响。该宽度下完整工作台本已把图片堆到正文上方，常驻侧栏过窄；超过 1160px
时恢复常驻侧栏，宽度默认跟随视口（见 `--sidebar-track`）。

紧凑层（≤1160px）同时为可读性抬一档：字体变量放大到 19px 基准，可编辑输入字段强制
≥16px（避免移动端浏览器聚焦时自动放大页面；门户渲染到 shell 外的弹窗字段同样覆盖），
按钮与目录行高加大到 52px。页面工作区不常驻大预览，候选以横向缩略条展示、点按打开大图，
缩略条按项目画布比例（`--canvas-aspect`）与固定高度预留尺寸，无候选或加载中也不收起，
加载状态由候选栏刷新按钮的转动图标表达，不插入文字横幅；
候选的删除与详情通过长按菜单进行，历史候选弹窗保留完整选择操作。
单页底部提供“上一页／下一页”翻页栏（复用未保存修改的离开确认），剧情总览仅阅读工具栏吸顶，标题和全项目统计随正文滚动，
长页面滚动中随时可用定位下拉跳回。这些规则集中在 `styles.css` 末尾的紧凑层区块，
类级小字号例外由高优先级选择器统一覆盖，不逐处维护。

翻页栏固定显示“← 上一页标题”、当前位置／总页数和“下一页标题 →”，标题过长时截断；
首尾显示“已是首页／已是末页”，正文留出底部安全空间。剧情按目录顺序跨情节、跨章节连续
翻页；角色视觉页只在当前角色内翻页。没有候选的页面也参与翻页，首尾按钮禁用，不循环。
切页后正文与页面编辑区回到顶部，后台更新不改变阅读位置。

超过 1160px 的宽视口不显示翻页按钮；使用 `Ctrl + ↑ / ↓` 切上一页／下一页，
`Ctrl + ← / →` 切当前页候选。普通方向键不再切候选；大图仍用无修饰的左右方向键切候选。
输入框、文字编辑区和弹窗／菜单打开时不触发工作台快捷键；切页复用未保存修改的离开确认。

目录以固定在视口左侧的原生模态抽屉打开，目录独立滚动，背景暂停滚动，关闭后保留阅读位置。
选中目标、点击遮罩、关闭按钮或按 Esc 都可收起目录。候选列表在主图高度内独立滚动。

## 公共滚动策略

滚动方式只按指针类型区分：`pointer: coarse`（触屏）使用文档级自然滚动，鼠标工作台使用
固定高度面板。因此手机请求桌面网站时仍有完整功能，但不会重新锁住文档，浏览器负责页面
缩放后的平移与下拉刷新，不用 JS 接管这些手势。

策略集中在 `styles.css` 的工作台根节点，通过 `--workbench-content-height` 和
`--workbench-overflow` 供外壳、导航及主内容消费，不在各页面重复识别设备。
大屏编辑面板的固定高度规则仅作用于 `pointer: fine`；候选列表、目录抽屉和弹窗仍保留
各自需要的局部滚动／临时锁定，不继承正文的滚动方式。

滚动改动须分别验证触屏工作台（含超过 1160px 的宽视口）和鼠标工作台。
桌面缩窄窗口不能替代手机实测：请求桌面网站后，双指放大再单指平移，并在正文顶部下拉刷新；
关闭抽屉／弹窗后重复检查。普通单元测试不能证明浏览器原生手势可用。

## 完整工作台

### 临时浮层与正文折叠

项目切换、环境和任务详情使用 `app/src/Popover.tsx`，不要用裸 `details` 模拟临时浮层。
组件默认点击外部、再次点击入口或按 Esc 收起，三个入口互斥；选择项目和跳转页面通过
组件提供的 `close` 回调关闭，刷新环境和任务控制等内部操作不自动关闭。

右键菜单等自定义定位浮层复用 `use-dismissable-layer.ts`。
入口与面板共同算内部区域；外部指针事件在捕获阶段判断，但不阻止外部目标的正常操作。
Esc 只关闭最上层临时浮层；右键菜单在外部滚动时收起，内部滚动不关闭。
调用方保留自身保存／取消语义，公共关闭逻辑不自动提交输入。

剧情章节、日志、文案说明等正文内容继续使用普通 `details`，不参与外部点击收起。
编辑／确认弹窗继续使用 `Modal`，保留 `busy`、`dismissible` 和调用方的未保存确认，
不要用临时浮层的关闭逻辑替代这些保护。

左下「项目」弹出菜单直接选择基本信息、生成设置、参考材料、任务历史，并管理当前项目；嵌字样式只放在输出分区，与成品并列；对比实验放在工具中，
仍绑定当前项目。单页嵌字区提供跳转项目嵌字样式的入口。嵌字设置统一管理
项目级字体、排版样式和角色文字颜色，逐页文字位置仍在单页工作区的“嵌字”子菜单编辑。项目字号使用宽 1024px
的逻辑画布坐标；设置页、角色页与视觉页统一按视觉画布的当前显示宽度等比缩放。

“系列”分区标题的右键／长按菜单提供故事总览和 Prompt 总览入口；点击章节或单元打开对应范围的剧情总览。
故事总览（`tab=project-story`）支持全文、章节和情节单元范围。内容栏内的阅读目录始终展开全部章节与单元，最小单位为 seq；左侧项目导览仍可深入每一个剧情页。局部范围仅挂载对应正文与分页卡片，工作台事实仍使用现有完整快照。阅读目录在桌面常驻并独立滚动，窄屏放在正文上方。导航请求只定位一次，后台状态刷新不改变阅读位置。
采用紧凑的正文阅读布局，左上方可快速定位。章节标题前显示 Chapter 序号，情节单元显示章内 Sequence 序号；
摘要直接跟在标题后，不重复显示标题。分页区不单列页数，文案区不再额外显示标题。
每个情节单元的分页以小卡片横向排列，通过横向滚动条或触屏滑动浏览。卡片显示标题、两行画面内容短摘及
候选列表第一张图片的完整缩略图；只有屏幕内的卡片串行刷新各自 PageKey 媒体，不读取任务列表或刷新全量事实。
有文案的页面按页码在卡片下方紧凑列出。点击卡片或文案页标题进入唯一单页工作区。
提供独立“重命名”和摘要“编辑”入口，草稿显式保存或取消；未分页的情节单元也显示摘要。

## API

- `GET /api/projects/:id/workbench`：从 outline、页面 narrative/goal、页面 Prompt、角色 profile/visual/
  Prompt 和统一嵌字设置组装当前事实 view model，不扫描候选媒体。
- `GET /api/projects/:id/revision`：只读轻量事实 revision，用于后台同步。
- `PUT /api/projects/:id/workbench/story-summary`：只修改一个梗概或摘要，body 为
  `{ target, text, expected_sha256 }`。target 为 `{ kind: "synopsis" }` 或
  `{ kind: "chapter" | "sequence", id }`；指纹来自工作台 `synopsis_sha256` / `summary_sha256`。
  请求使用目标级写入；项目操作锁内核对目标文本 SHA，保留所有其他摘要、标题、ID、
  顺序与页面。空白、额外字段、未知目标和过期内容均拒绝，不提供 outline 全量写入口。
- `POST /api/projects/:id/workbench/page-media`：按完整 PageKey 无候选写锁读取候选列表；
  单文件原子读取，跨文件短暂变化在下次同步收敛，不把 busy 暴露给候选展示。
- `GET /api/projects/:id/workbench/candidate-counts`：读取完整 PageKey 到可用候选数的稀疏映射与独立版本，不读取页面事实或图片字节。
- `PUT /api/projects/:id/workbench/page-prompt`：完整替换一个剧情页或角色视觉页 Prompt；
  body 包含 `kind`、`page_id`、`prompt`、`expected_sha256` 和 `expected_context_sha256`；
  后者取工作台 page.prompt_context_sha256，保护页面内容与实际角色配置。
- `PUT /api/projects/:id/workbench/character-prompt`：完整替换一名角色的 `prompt_name` 和各子设定的
  自由文本与参考图；body 包含 `character_id`、`prompt`、`expected_sha256` 和 `expected_visual_sha256`。保存时重新读取
  visual 并要求其指纹未变化。Prompt variant key 必须来自当前 visual；暂时缺少尚未建立的下游
  variant Prompt 只返回诊断，悬空 key 拒绝。
- `PUT /api/projects/:id/workbench/character-profile`：完整替换一名角色的 `name` 和 `description`；
  body 携带目标 `profile_sha256`。
- `PUT /api/projects/:id/workbench/character-visual`：完整替换角色视觉描述和已有子设定的名称、描述；
  body 携带目标 `visual_sha256`。该入口不允许增删或重排 variant ID，结构调整继续使用导航语义命令；
  子设定改名在角色页「子设定」区块直接编辑，保存时服务端原子联动更新 visual/prompt/角色视觉页/剧情
  narrative 的全部引用。
- `PUT /api/projects/:id/workbench/page-content`：以完整 `PageKey` 和目标 `content_sha256` 保存单页内容。
  剧情页完整替换 `title`、`scene_description`、`characters`、`dialogue`，角色视觉页完整替换 `title`、
  `visual_goal`。画面内容的填写要求、20 字上限只属于创作规范；页面编辑器
  显示画面内容字数与超长提示，空白或超长均不阻止保存或生成。保存接口同时
  返回 `warnings` 和 `downstream_diagnostics`；warnings 包含超限字段的当前字数、20 字上限和中文精简建议，与 Agent `narrative save`
  使用相同规则；警告不写进项目事实。新增对白不能指定持久 ID，由服务端生成
  `dialogue-<12hex>`。当前 Prompt 或嵌字仍引用
  被移除内容时允许保存，并返回 downstream_diagnostics，不跨文件自动修正。
- `PUT /api/projects/:id/workbench/page-lettering`：以完整 `PageKey` 和全局布局文档
  `layout_sha256` 只替换目标剧情页的 `items`；布局必须引用本页当前对白。
- `GET /api/projects/:id/workbench/page-text-sources/:pageId`：读取某页 text-sources 草稿
  （document + 目标与上游指纹）；`DELETE` 同路径删除单条映射，body 携带 `dialogue_id` 与两个指纹。
- `GET /api/projects/:id/workbench/text-source-context?source_file=…&offset=…`：按语料相对路径与字节
  偏移返回原句 ±2 行上下文；source_file 必须解析在所属项目的 `writing-corpus/` 内。
- 主预览默认以 DOM 叠加已保存文案，缺少布局时补默认位置；可直接拖动与调整尺寸，不请求合成 PNG。
  草稿归属于页面，切换候选和后台刷新不重置草稿；保存位置按钮保留在「嵌字」子菜单。
- `POST /api/projects/:id/workbench/render`：以完整 `PageKey` 发起单页候选任务，支持
  `count` 1 到 3 和可选 `seed`；服务端在当前事实下重新编译并冻结任务。
- 两个 Prompt 写入均通过目标级 Interface 核对目标 SHA-256 与必要依赖，不因无关页面变化失败。冲突返回 409，
  浏览器拒绝旧保存并后台重新载入最新事实，不重试旧写入；服务端返回正规化文档与新 SHA。
- `POST /api/projects/:id/workbench/candidate-detail`：以完整 `PageKey` 和 `candidate_id` 读取该候选冻结的
  Prompt、LoRA、seed、route、recipe 与 workflow 身份；不依赖任务里的陈旧绝对路径。
- `DELETE /api/projects/:id/workbench/candidates/:candidateId`：以完整 `PageKey` 删除候选，尽力把仍存在的
  任务历史条目标记为 discarded；历史更新失败不恢复已删除成果，活动任务的候选会被拒绝。
- `DELETE /api/projects/:id/workbench/candidates`：批量接收 `candidate_ids`；或以 `generation_mismatch: true`
  清理与当前生成条件签名不符的全部候选（缺签名视为不符），可携带前端计数时使用的
  `expected_signature`，与服务端重算结果不一致时返回 409 `candidate_generation_signature_stale`；
  当前 Prompt 无法编译时返回 422 `current_prompt_unavailable`。生成详情随成果保留，不依赖任务历史。
- `PUT /api/projects/:id/workbench/lettering-settings`：携带目标 SHA 完整替换
  `lettering/settings.json`，一次保存字体、字号、文案框预设和全部角色颜色。
- `POST /api/projects/:id/workbench/navigation/:action`：执行导航右键菜单对应的窄语义命令。当前 action
  覆盖章节、sequence、剧情页、角色、角色子设定与角色视觉页的创建、重命名、锚点移动排序、复制和删除；
  每个 action 只接受自身所需字段，新 ID 均由服务端生成。所有事实写入继续使用项目 expected revision，
  冲突返回 409，不自动重试。

浏览器用户是最高权限操作主体：总览中的梗概和摘要，单页中的标题、画面内容、出场角色、文案，角色视觉页的标题与目标，
角色 profile、visual 描述和已有子设定内容，以及两类页面 Prompt 均可编辑：设定页编辑 `prompt_name`、各子设定
整段文字和参考图；剧情页编辑本页文本、引用文字（编辑即整段 override，可恢复继承）、图片选择和可带用途的附图。
这些修改使用显式保存；切换项目、页面或
角色设定前必须处理未保存修改。

页面 Prompt 与设定 Prompt 共用自由文本编辑控件和草稿转换模块。

Agent 的 Prompt 自主调整范围和 LoRA 授权要求仅约束 Agent 行为，不限制用户在工作台的直接编辑权。
章节、sequence、页面归属、角色与子设定的增删和排序继续使用导航语义命令或 Agent 编辑入口；工作台
通过各文件的窄契约编辑 narrative/goal/profile/visual，不提供万能 JSON 编辑器。角色 visual 内容保存
不会自动改写 Prompt；若 variant 结构已变化，工作台同步最新结构后仍需处理下游文件。

## 后台同步

工作台每三秒串行查询当前项目 revision，隐藏标签页暂停此查询。不变时不读取完整工作台；
变化时后台获取快照，不清空画面、不设置全局 loading、不重挂编辑器。当前 PageKey、编辑 Tab、
面板宽度、焦点和滚动保持；只有当前页被删除时选择同 owner 邻页。
Agent 修改当前 Prompt 或内容时直接覆盖对应浏览器草稿，不保留双版本，也不弹出冲突选择。
其他页变化不会重置当前输入，用户自己保存后的 revision 不触发重复载入。
材料、生成配置与 LoRA 工具页的独立事实缓存也参与快照同步：先准备与 workbench 相同 revision
的数据，检查项目/页面切换及在途写入后一起应用，最后推进写入 revision。准备失败不提前推进版本。

候选区每 2.5 秒独立串行检查当前完整 PageKey 的媒体版本，隐藏时暂停，不依赖任务历史。
媒体响应有独立 `revision`；带 `x-story-canvas-media-revision` 请求头时，版本相同只返回
`{ unchanged: true, revision }`，前端不更新状态。新候选和旧候选删除都能同步；
其他页面变化不改变当前页媒体版本。服务端初次建立按 PageKey 分组的成果索引，之后按文件通知
只重读变化页面的 result.json 并检查图片是否存在，不读取 manifest 或图片字节。重复通知合并，
扫描途中到达的通知保留到下一轮；未变化页面的媒体投影继续复用。每分钟或遇到无法定位页面的
通知时全量补偿校验。文件监听创建失败或运行报错时记录 `[page-media]` 日志，退避 5 秒后由
后续媒体／数量请求重建监听，恢复订阅时补查中断窗口；正常读取不额外周期扫描当前页。
候选标题旁的刷新图标和显式媒体操作后的读取带
`x-story-canvas-media-fresh: 1`，强制重读当前页并更新其数量，不等待文件通知；
普通切页不强制扫描。后台读取保留旧媒体，失败后由后续轮询重试；
迟到的旧页响应丢弃。候选滚动只跟随用户主动切换预览，不跟随后台列表更新。

顶部任务状态轮询只读取活动任务与精确跟踪的终态；生成历史打开时按需读取，每页 30 条，通过
“加载更多”可查看全部，不设最近 8 条的截断，也不在每次轮询中读取整段历史。
任务卡片直接展示本次已生成图片，点击缩略图进入全屏并可切换同任务图片。图片地址在列表打开时
按任务单独读取，活动任务随状态与成果数量变化刷新，不增加后台轮询；已删除图片不再展示。
取消按钮在请求期间转圈并禁用重复操作；成功后立即应用服务端返回的状态。
当前生成尚未结束时显示“当前生成结束后取消”，失败时提示原因并恢复按钮。

导航仅显示「N 张」；初次数量未知显示「—」，已读快照没有对应键视为 0。
数量每 2.5 秒独立串行刷新，直接汇总同一份按页媒体索引，不再重复检查图片文件；
仅数量变化改变版本。候选索引的文件检查限制并发；读取失败保留旧快照，切项目丢弃迟到响应。
候选原图按稳定 UUID URL 使用私有不可变缓存，主图优先加载，缩略图延迟加载；拖动嵌字不下载原图。

## 当前边界

页面顶部「保存」统一保存页面内容与逐条嵌字布局，Prompt 保持独立保存。浏览器先提交内容，
取得服务端生成的文案 ID 后再提交布局；文件和领域 API 仍分开。未保存文案用临时草稿标识参与
预览与操作，正式 ID 按保存快照中的文案顺序映射，保留位置与爱心参数。删除文案同时过滤其布局。
保存期间冻结编辑，避免中途接纳的内容快照覆盖布局草稿；只有两步都成功才提示保存完成。
内容成功、布局失败时保留正式 ID 和布局草稿，再次保存只补交布局，不重复创建文案；这不是跨文件原子事务。

嵌字文案 `mode` 包含 `heart`，可不指定 speaker，也可关联项目角色或 NPC；颜色固定为粉色。
逐条布局的可选 `heart` 保存 `font_size`、`rotation`、`seed`，默认参数通过文案 ID 稳定初始化，
不写入项目统一字号。`app/shared/heart-lettering.mjs` 在 100 单位字号下进行确定性排布，
浏览器 `HeartLettering.tsx` 等待内置字体加载后测量字形并绘制 SVG；字体与爱心轮廓均随应用发布，
运行时不依赖图片生成或 Python。位置、选择、保存与边界提示沿用公共嵌字逻辑；爱心按方向旋转中心点，逐字与装饰轮廓保持正立；正立字形重新避让后的
包围框由内容推导，布局中的框宽高不参与艺术字缩放。单条字号作为唯一缩放值。

旁白（`mode: "narration"`）是另一种特殊格式：每页至多一条、不超过 100 字（服务端强校验），
在嵌字页签的专属文本框编辑；渲染为通栏渐隐字幕条，条目上的可选 `position`（`"top"` / `"bottom"`，缺省底部）按页选择顶部或底部，
沿用项目统一字体字号、固定配色，
不可拖动、不参与逐页布局——`dialogue-layouts.json` 拒绝保存旁白位置，嵌字设置也不再有旁白预设。

文字页（narrative 的 `page_kind: "text"`）是无画面剧情页：目录名称 `title` 与显示标题 `display_title` 分开，正文为 `body`，`characters`/`dialogue` 必须为空，
类型创建时定死，内容保存按页型区分键集合；`compilePageRenderTarget` 直接拒绝渲染，工作台隐藏 Prompt/嵌字/生成详情页签与生成入口，
右侧候选区替换为黑底实时预览（`TextPageArtwork`，与成品输出共用）。剧情总览的文字页缩略图渲染同一组件的迷你版，
随内容保存即时更新并纳入 F9 隐藏图片；嵌字样式不可用时回退为目录名称黑卡。`text_layout` 保存标题／正文字号、各自对齐与整组位置；
缺省为 `defaultTextPageLayout`，新建页面显式写入默认值。显示标题缺省为空，不从目录名称推导。浏览器内容保存传入完整 `display_title` 和 `text_layout`。
字号 12–192，位置为 `upper`／`center`／`lower`（中心高度 1/3、1/2、2/3），对齐为 `left`／`center`／`right`。
共享组件通过尺寸观察在字号、内容、字体或画布变化时向内收长文；溢出时编辑器提示，成品渲染拒绝输出。目录重命名不影响成品过期判断。
文字页端到端验证：先构建，再运行 `node --test app/tests/browser/text-pages.test.mjs`，覆盖真实保存、无标题、独立排版、比例一致、溢出拒绝、剧情总览缩略图即时更新与 F9 隐藏。

浏览器验证：`node --test app/tests/browser/heart-lettering.test.mjs`，使用临时 Vite 与本机 Edge，
不读取或修改用户故事项目；覆盖独立调整、骰子、拖动缩放、类型切换与重载复现。

工作台仅通过明确领域入口编辑页面内容、Prompt、统一嵌字设置、逐页嵌字布局、候选生成与删除和导航结构，不恢复 assessment、
Prompt reference、旧聚合文档、万能 JSON 编辑器或兼容写路径。所有保留候选均可预览，不再维护选用状态。项目复制只携带事实和输入，不复制候选、输出、任务或缓存；Git 同样忽略生成结果。

左侧导航保留原工作台的右键入口：数据集节点创建数据集；角色、设定和角色视觉页按当前文件边界
提供对应操作；章节、sequence 和剧情页按当前三级结构提供对应操作。数据集子项、项目、资源、训练任务、
训练记录和模型节点没有自身语义菜单时不显示菜单，也不会冒泡成父节点菜单。

角色子设定 ID 由 `visual.json` 定义，可在角色页「子设定」区块直接改名；保存时服务端原子联动更新
visual/prompt/角色视觉页/剧情 narrative 的全部引用。导航中新建子设定只写 visual，并返回缺少下游
Prompt 的诊断；
用户可在角色设定页显式建立并保存该子设定的 Prompt。从左侧导航删除子设定时，同一显式删除动作会
一并清理对应 Prompt；仍被剧情页或角色视觉页使用的子设定会被拒绝，最后一个子设定也禁止删除。
这个组合操作不建立日常双向同步。

文字页预览和输出共用工作台 `render_capabilities.text_page` 的实际成品尺寸（生效 recipe 尺寸 ×2），不以项目名义宽高比代替。尺寸解析失败时仍可编辑文字，预览标明草稿并禁用输出。

## 轻量性能日志

服务端自动写入 `Saved/Logs/performance.jsonl`，单文件约 5 MB 后轮换到
`performance.jsonl.1`，只保留一份旧文件。日志是可清理派生物，不提交 Git。

- `kind: http`：API 方法、路径（不含查询参数）、状态码、处理耗时、响应长度和是否中断。
  快速成功的健康、硬件、任务列表轮询不记录；超过 500 ms 或失败仍记录。
- `kind: browser`、`event: workbench-load`：前台工作台载入开始到数据被接纳的总耗时，
  包含等待已有保存及关联数据读取。`applied` 为已接纳，`discarded` 为被切换或新请求淘汰，
  `failed` 为失败。后台刷新不单独上报浏览器计时。
- 浏览器与对应工作台 HTTP 请求用 `request_id` 关联。两者耗时差不等于纯前端计算时间，
  还包含网络、保存等待和关联读取。浏览器终点在 React 绘制之前，不代表图片或界面已显示；
  当前也不测量从用户点击到事件处理开始的等待。

浏览器通过 `/api/performance` 尽力上报，关闭页面或网络异常时可能丢失；日志失败不影响业务。
不记录请求体、Prompt 或正文。排查时先按接口/操作查看慢记录，再针对性增加阶段计时；
当前不引入监控平台、数据库或统计面板。
