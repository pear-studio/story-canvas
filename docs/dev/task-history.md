# 任务历史、业务摘要与自动清理

## 目标与现状

任务记录是近期运行与排错入口，保留上限为每个剧情项目最近 500 条候选终态任务。活动任务不计入上限。候选、成品和对比实验成果有各自生命周期，历史清理不删除这些成果。

当前历史接口对所有项目逐个读取全部历史 state.json，完成排序后才取 30 条。实测一个项目有 2940 条历史；运行服务首屏及后续页约 6.9 秒。独立进程扫描约 1.3–2.2 秒，差额尚未定位，不能把全部耗时归因于磁盘扫描。前端每页还会立即请求所有卡片的结果列表。

候选图片、生成详情及成品制作读取 Outputs 中独立的 result.json、generation.json 和媒体。候选批次清理仍读取原任务的完成状态与预期数量；候选总览图读取所有任务确定每页最近一次生成。这两处依赖必须先解除。最新任务即使失败或零图也不能回退到旧成功任务。

## 第一版范围

1. 候选历史持久引用索引，先合并排序与分页，再读取当页状态。
2. 每页最近任务的业务摘要，以及仍有候选的批次摘要。
3. 空闲项目的候选历史自动保留 500 条，删除过期完整档案及专属调试文件。
4. 任务卡片进入可视范围后才请求结果列表，不引入页面或内存历史缓存。

成品任务按页面与语言覆盖保存，不随运行次数累积；保留现有成品运行状态。对比实验记录承担实验查看、结果与重试，第一版不自动删除实验及成果，历史仍使用现有独立读取入口。500 条上限明确只适用于候选任务档案，不能称作所有类型统一上限。

## 存储职责

| 数据 | 存储 | 生命周期与用途 |
|---|---|---|
| 活动与近期候选任务 | Saved/render/active、history/<task ID> | 原冻结 manifest 与可变 state；活动恢复、详情、排错 |
| 历史引用 | Saved/render/history-index.json | 版本、代次、任务 ID、标准化排序时间；仅引用终态任务，不复制计数或项目路径 |
| 业务摘要 | Saved/render/business-summary.json | 每页最近任务的 ID、创建时间、状态、该页条目身份与状态；有现存候选的批次状态、创建时间、各页预期数量 |
| 成果与生成详情 | Outputs/pages/<page ID>/<candidate ID> | 独立媒体、result、generation；不受任务保留上限影响 |
| 未完成派生更新标记 | Saved/render/catalog-dirty.json | 源记录与两个派生文件更新或清理中断时触发修复 |
| 摘要初始化标记 | Saved/render/business-summary-required.json | 首次摘要发布后单调写入；索引重建不移除它，缺失摘要时禁止猜测恢复 |
| 清理待办 | Saved/render/cleanup-pending.json | 已严格预检、摘要已保存的待删除任务 ID；维护幂等完成，普通 GET 不执行或清除 |

业务摘要不包含 Prompt、workflow、冻结输入、提交详情或图片字节。每页摘要覆盖更新；批次摘要随候选保留，最后一个候选显式删除后移除该批次。页面删除会把候选归档以支持还原，因此第一版保留其业务摘要，不仅凭当前页面索引回收。摘要数量随页面及候选批次增长，不随全部生成尝试增长；摘要不受 500 条档案上限裁剪。Saved 的离线整体清理仍会丢失运行摘要，不能承诺恢复失败或零图的历史。

## 写入与一致性

候选存储内增加项目级 catalog 文件锁，所有任务创建、读取、更新、派生重建和清理遵循 catalog 锁 → task 锁的唯一顺序。媒体发布、删除和维护的外层顺序为 candidate mutation → page/media（若需要）→ catalog → task；catalog 内不反取候选锁。项目间互不阻塞。复用现有 PID、失效锁和原子替换语义；不新增数据库或事件日志。

写入前确认派生文件可读且无 dirty；否则在锁内重建。写 dirty 后提交源任务，再更新业务摘要及历史索引，最后清除 dirty。源状态已提交但派生更新失败时不把任务执行报成失败、不重新执行远端生成；保留 dirty，下一次读取或维护重建。源写入本身失败仍报告原错误。

索引重建直接读取原子源状态，不调用会重复获取锁的公共任务读取接口；包括归档失败而仍处于 active 的终态。业务摘要清源后承载唯一运行信息，必须保留，不能用仅剩 500 条档案覆盖。首次摘要原子发布后写独立初始化标记，源删除前确认标记已持久化。标记存在而摘要缺失、损坏或版本未知时，业务查询和清理明确报错；索引仍能独立重建。标记不存在且摘要不存在时才允许首次全源初始化；摘要存在时始终校验并合并保留。

候选删除统一使用持久删除意图，覆盖源存在与已清理两种分支：catalog 锁内先保存意图，再原子移走整个候选目录，成功后更新源条目（若仍有源）与业务摘要，最后一张候选移走后移除批次。移动失败时源和摘要均未改变。中断恢复以候选目录是否已移走判断提交，任务读取也先完成未提交的删除投影，避免执行器重新发布。总览的最新任务不回退。

正常查询读取项目历史索引，在当前登记项目 ID 下生成既有 taskHistoryKey，跨项目与其他任务类型排序。选择当前页与 lookahead 后只读取所需源状态。读取期间若清理使引用消失，刷新引用并有界重试；游标取实际返回最后一条。相同时间继续使用用途、任务 ID、项目 ID 的完整排序键。新任务插入和删除维持既有实时游标语义，不承诺跨页固定快照。

索引缺失、损坏、版本不符或 dirty 时进行一次锁内重建。正常读取无全量 state 扫描；外部手改源记录需要显式重建。索引重建是派生数据修复，不迁移项目事实。当前原子替换支持进程中断恢复，不额外声称断电 fsync 保证。

## 自动清理

启动恢复循环结束，以及任务退出生成队列并取得最后响应快照后执行项目维护。维护在 catalog 锁内复查项目没有活动候选和队列引用，保证执行器不再读取被删档案；维护失败独立记录，不把已完成生成改判失败。清理不在历史 GET 中触发，首次打开只修复索引和未完成的源更新投影。

同步生成入口消费执行器在维护前取得的最终任务快照，不在维护后重新读取可能已过期的档案。新取消任务记录真实取消结束时间，避免排队中的 worker 尚未退出时被当成过期记录清理；旧记录没有结束字段时仍使用既有创建时间回退。

按既有结束时间排序保留最近 500 条，时间相同按完整键排序。不以目录名称、创建时间或文件 mtime 代替结束时间。先持久保存全部必要业务摘要，再删除旧档案；删除范围仅为经过校验的本项目 history/<task ID>、progress/<task ID>.json、submissions/<task ID>。活动目录和 Outputs 不属于删除范围。损坏状态、链接路径或不能验证的现存成果应阻止对应清理，不把坏记录当成成功删除。

清源前严格逐条读取候选 result、generation 与媒体，检查身份和已有 hash，视频另检查视频文件；容错候选列表的缺席不能证明成果不存在。候选目录仍存在但内部缺文件、身份或 hash 异常时保留档案，因此异常或忙碌时允许超过 500，下一次可维护时收敛。

路径边界检查通过后，严格 lstat 确认整个候选目录不存在（仅 ENOENT）时，可以清理对应旧档案；访问错误或链接不作为缺失。仅当页面仍登记且整个页面成果目录存在时，回收批次摘要中的缺失候选 ID，最后一个 ID 回收后移除批次。页面未登记或整个页面目录不存在时保留批次摘要，兼容页面归档、移动与还原。每页最新任务的 available 状态仍保留，总览据实际媒体标记 missing，不伪装成显式 discarded。

摘要先保存，随后写本次已预检任务 ID 的 cleanup-pending，更新索引排除待办，再逐项删除源和专属文件，最后更新或清除待办。部分失败保留待办，下次空闲维护幂等完成；索引扫描排除待办任务，即使其 state 已部分删除也不将其误判为普通坏源。普通 GET 不执行待办、不抹除它。源 mutation 的 dirty 与清理待办分别管理。恢复必须保留先前业务摘要，不能复活删除记录或重复生成。

首次维护面对已有几千条档案，需要一次完整读取与摘要建立；该成本与日常首屏分开统计。不在测试中清理真实项目，使用 Saved/Tests 隔离目录。部署后第一次空闲维护会实际清理旧候选任务档案，旧档案的任务级排错信息不再可查，候选自身生成详情仍保留。

## 前端与性能验证

TaskResultStrip 使用 IntersectionObserver 观察稳定容器，进入可视区域才发 metadata 请求；卸载或关闭取消请求，身份变化重置状态，失败仍可重试。原生 img lazy 只负责图片字节，不替代 metadata 懒加载。

服务端历史读取分别测量索引/修复、其他任务源、选页状态、总耗时。验收记录清洁索引首屏、下一页、首次修复和首次维护的耗时与文件打开数量；不预先承诺固定毫秒数。已有约 3000 条和合成大量任务下，正常候选历史只读取当页所需状态；小型引用顺序读取仍是 O(N)，维护完成后 N 不超过 500。

## 回归要求

- 排序使用结束时间，跨项目、同时间和不同用途稳定；无并发变化时完整游标无重复遗漏，有变化时遵循实时列表语义。
- 最新失败/零图任务、部分结果、候选丢失或删除仍被总览正确识别；旧任务清理后批次清理行为不变。
- 保留上限、活动保护、项目隔离、调试文件回收，媒体和生成详情字节不变。
- dirty 各中断点、损坏索引、并发创建/更新/读/维护、归档失败、失效锁恢复，不重复执行生成，不死锁。
- 派生重建不会丢失已清理任务的业务摘要；最后候选删除后回收批次摘要。
- 可视卡片请求、关闭取消、滚动新增请求、失败重试；类型检查、相关服务测试、浏览器回归及完整测试。

第一版限制：对比实验与成品不设统一档案上限；忙碌项目、无法验证资产的旧档案可以暂时超限，维护报告原因。索引与业务摘要初始化需要一次全源扫描；不可重建摘要损坏时明确报错。页面归档删除的业务摘要随项目保留，以支持还原。没有增加缓存、数据库或后台常驻服务。
