# H3 动态页

动态页使用 `page_kind: "video"`，与插画、文字页共用剧情索引、排序、PageKey、生成队列和成品入口。首版仅支持剧情归属，模型固定为 H3，配置为 `minimax-h3`；页面类型不能在创建后改变。

## 输入与生成

目录单元菜单或页面右键菜单可新增动态页。输入图选择器默认指向正式剧情顺序中前一张插画页，跳过文字与动态页；该页没有候选时显示空列表，不回退或自动挑图。也可选择项目中的其他插画／设定验证页。

选中候选后复制到 `materials/`，H3 只保留一张输入。条目的 `origin` 保存来源 `page_id` 和 `candidate_id`；后续移动页面、删除来源候选或重新生成不会改变已导入输入。重新导入会明确替换当前输入。通过通用 `reference.save` 也可导入本地图片或已有材料。

`prompt.json` 的 `models.h3` 保存独立中文或英文动作描述，不隐式追加角色和场景 Prompt。当前默认配置为裁剪版 H3 FL2VA INT8 ConvRot，不加载 LoRA。配置级 LoRA 仍可由 `minimax-h3` 统一声明，预检、生成详情与冻结任务保存相同的文件身份和权重；启用时通过模型专用 LoRA 节点同时连接 guider 与 scheduler。页面尚不支持独立 LoRA 编辑和 Prompt 重写。

| 字段 | 当前契约 |
|---|---|
| `text` | 动作描述；非空才可生成 |
| `reference_images` | 一张已导入输入图 |
| `duration` | 3–15 秒，默认 5；5 秒以下为短片实验设置 |
| `loop` | 默认 false；true 时同图绑定首帧和尾帧，并加入返回起始姿态的约束 |
| `quality` | `preview`（界面为“低分辨率”） / `standard`（标准尺寸）；短边约 576 / 768px，保持输入比例、尺寸按 32 对齐，总面积不超过 768×1344 |
| `steps` | 8–50，默认 20 |

原生帧率固定为 24fps。帧数为 `17 × round((24 × duration − 5) / 17) + 5`；页面显示换算后的实际时长。请求 3 秒得到 73 帧／3.04 秒，5 秒得到 124 帧／5.17 秒。首尾约束不能保证视觉接缝完全自然，需要实际播放验收。

H3 工作流内部使用模型要求的视频／音频 latent，只解码视频，导出 MP4 不包含音频流。没有插帧、超分或二次采样。动态页默认生成一个候选；插画仍默认三张，显式 count 覆盖默认值。

## 成果与成品

候选目录保留 `video.mp4`、首帧封面 `image.png`、带时间与帧号的 `review.jpg`、生成详情和媒体记录。发布前通过已配置 ComfyUI Python 环境中的 PyAV 完整解码，核对帧数、24fps 和无音频；封面仍使用当前候选媒体身份，其他文件随候选一起删除。任务冻结时包含时长、循环、尺寸档位和步数，之后的页面编辑不会影响原任务。

网页提供 WebP 下载、抽帧审阅、生成详情和候选删除，不提供单页 MP4 下载。成品内部仍复制候选 MP4 和封面，不走图片超分或嵌字；MP4 只用于原始成果留存和查看原图时的暂停／进度控制。成品媒体 ZIP 保留正式页码，静态页输出 PNG，动态页输出最大宽度 1024px 的动画 WebP，放在“动态页”目录；嵌字／无字版本选择只作用于静态页，动态页始终只收录一次。离线 HTML 内嵌静态与动态 WebP 自动播放，不含 MP4。首版不导出 GIF，不向动态画面叠加对白。

工作台的动态候选、任务结果和成品缩略图使用 320px 动画 WebP，大图与连续阅读使用最大宽度 1024px 的动画 WebP，不放大原始画面。点击大图的“查看原图”后才加载原始 MP4，显示原生暂停和进度控件，可返回动图预览；动态候选只提供 WebP 下载。

MP4 是原始成果，WebP 是可重建的预览与导出缓存。项目媒体 URL 带 `?w=320` / `?w=1024` 时返回 WebP，省略宽度时返回原始 MP4。缓存位于项目 `Saved/media-cache/`，按源文件身份和宽度失效，发布新候选／成品后后台预热，已有成果首次读取时生成并缓存。转换沿用已配置的 ComfyUI Python 环境和 PyAV／Pillow，缩略档质量 75、大图档质量 80，保留所有帧及实际时长，播放无限循环；它不改变 H3 的首尾约束。Agent 的 `absolute_video` 仍指向 MP4 原图；CLI／DSH 的 `finished.export` 与网页共用 WebP 导出路径，不增加格式开关。

动态页沿用公共页面标题、面包屑、面板和按钮样式。PC（>1160px）使用编辑／视频预览双栏，鼠标环境下两栏独立滚动；紧凑布局通过底部“候选”打开视频面板，正文不常驻视频，保存和生成与其他页面共用底部操作条。手机（≤680px）采用 16px 输入字号和至少 44px 控件区域，生成条位于翻页条上方。输入图选择收进导入弹窗，步数、数量和 Seed 收进“更多参数”。

## Agent 与 DSH

CLI 与 DSH `story_canvas` 共用一份注册表和指纹契约。典型流程：

1. `page.create`，`page_kind:video`；用 `page.editor.read/save` 编辑标题。
2. `page.video.source` 查询默认前页或指定 `source_page_key`，用户选择候选。
3. `reference.list/save`，target 为 `{kind:"page",id:动态页ID}`，来源 `page_key` 与 `candidate_id` 指向插画候选。
4. `prompt.read/save` 修改当前 H3 输入，沿用读取回执的保存参数。
5. `generation.page.inspect` 预检；`generation.run`；`task.wait` 等待原任务，默认10分钟、最多30分钟，超时按回执续等。
6. `task.results` / `candidate.list` 返回 `absolute_video`、`absolute_review` 和实际媒体元数据；Agent 使用 `read_image` 审阅拼图，抽帧不能证明连续播放的流畅度或接缝自然。
7. `finished.output`、`finished.jobs/inspect`、`finished.export`。

极简预设仍禁止生成。工具代码变更后先 `status`；`reload_required:true` 表示 DSH 进程加载了旧注册表，应重载 DSH，不将磁盘新能力冒充已经加载的工具。

## 验证

任务结果接口的动态候选和成品都返回封面 `url` 与原视频 `video_url`。任务列表使用带宽度参数的原视频地址读取 WebP 缩略动图，点击后进入同一大图界面，默认播放 WebP，查看原图时切换 MP4；普通图片沿用图片灯箱。

`app/tests/video-pages.test.mjs` 覆盖时长网格、来源推荐、中文输入、任务冻结、单候选默认值、循环拓扑及混合阅读器；批量回执测试覆盖 3 张插画与 1 段视频的实际数量统计。2026-10-04 在 RTX 4090 上完成普通 3 秒和循环 5 秒、低分辨率、12 步的真实生成与网页验收；Kimi 在 DSH 中执行创建、导入、编辑、预检、生成、结果审阅及成品导出。验收媒体与回执保留在临时副本和 `Saved/Agent/`，不是工具 Git 内容。
