# 当前生成条件下的视觉叙事解法

本文保存当前主力模型、render profile 和工作流下，已经被实际成片证明有效的
剧本、分镜与分页解法。它帮助 Agent 在不损害叙事意图的前提下，优先选择更稳定、成本更合理
的静态画面表达；不是个人审美画像，也不是禁止创作困难画面的规则清单。

## 更新门槛

- 经验只能从用户明确确认验收的页面或工作单元中提炼。
- 选用候选、评估通过、完成生成、写入页面事实或 Agent 判断效果良好，都不等于用户验收。
- 无法确认页面是否已由用户验收时，先询问用户；不能根据项目状态或图片结果推断。
- 从验收页面提炼出的新增、修改或删除建议，还必须由用户明确确认后才能写入本文。
- 未验收页面暴露的问题只用于继续诊断、试验和修改，不能沉淀为全局经验。

项目不保存页面审批状态。验收与经验修改的确认留在会话中，文件历史由 Git
提供；本文不记录项目名、页面 ID、来源、证据、置信度、状态、日期或修订历史。

## 使用边界

- 本文补充[创作指南](guide.md)，不覆盖来源材料、项目硬约束、角色事实或用户明确叙事要求。
- 规则描述当前配置下的优先解法和替代方案，不把模型局限写成绝对禁令。
- Prompt、Seed、模型或执行故障能够可靠解决的问题，不转化为分页规避规则。
- 主力模型家族、render profile 或工作流明显变化时，相关规则需要重新验证；发生
  冲突时说明具体情境并由用户决定如何调整。

## 写法

每条经验只写一个可执行单元：

```text
情境：想表达的叙事或视觉关系。
优先解法：当前配置下优先采用的画面、镜头或分页方式。
替代方案：优先解法不适用时仍能保留叙事意图的做法。
```

不建立分层、评分或待验证经验池。相近规则直接合并，过时规则在用户确认后改写或删除。

## 人物互动与动作

情境：页面需要表现敲门、按键、递物或触碰等短暂动作；连续生成后，动作瞬间仍不稳定，而读者
只需知道动作发生，不需要看清准确过程。

优先解法：改画动作发生前一刻或后一刻。前一刻展示人物朝向目标、动作已经准备就绪；后一刻
展示目标状态或人物反应。由标题、对白、心理或旁白说明具体动作。

替代方案：当动作的执行方式或结果会改变剧情时，继续保留动作瞬间；改用更近镜头、姿态或构图
控制，或者拆成准备动作和动作结果两个页面。

## 情绪、对白与留白

情境：页面需要表达距离、动机、目的等不必直接可视化的抽象信息。

优先解法：画面集中表现当前可见动作与环境，通过对白、心理或旁白传达抽象信息，不强迫对应
地点、人物或符号入镜。

替代方案：当地点或事实本身必须由画面建立时，使用一个清楚的视觉线索，或另设页面承载。
