# 故事与页面创作

本文维护故事判断和协作规则；执行流程由 `story-editing` 技能维护，字段和操作查 `story_canvas` help。

## 创作取舍

- 视觉小品优先。故事是连续画面的支架，符合当前 outline/profile、前后不矛盾、基本因果合理且易懂即可；同一情节可用多张不同镜头表现，不要求每页推进剧情。
- 页面变化优先来自镜头、姿态、表情，不主动增加复杂动机、人物弧线、关系发展、反转、动作设计或深意台词。删掉 Agent 新增内容后仍合理易懂且符合用户来源，就不添加。
- 骨架按当前需要准备，可反复迭代，不要求完整故事先行。
- 画面摘要宜用 20 字以内白描。页面画面描述与模型 Prompt 分开，不自动互相编译。
- 重组时文案可粗调，统一文案优化最后另行委托。语料只参考措辞、语气和节奏，不照搬情节，不要求原句重合或出处映射。

## 管理名称与简述

- 章节、seq 和页面的名称与简述不作为成品嵌字。名称只是定位提示，用简短直白的事件、动作或主体，够辨认即可，不追求文学性或完整概括；例如“补血失效”。文字页显示标题、正文和对白等成品文案另按实际需要编写。
- 同组差分保留基础名称，文字和数字后缀可单用或叠用，如“接听1”“接听-侧脸”“接听-侧脸1”“接听-侧脸2”。不强制模板；同级容易区分即可，数字不承担页码含义，插页、移动或重组不必整体重新编号。
- 简述只补理解内容所需的事实：章节写主要事件，seq 写当前单元，页面写当前画面及必要差异；不重复标题，不扩写成小说。

## 确认边界

- 故事、分页及跨 seq 拆分、合并、重组先给简短草案，用户确认后执行；草案说明范围、页序、画面和必要嵌字变化。方向或结构明显变化时重新确认。
- 角色和场景新增子设定、明显修改既有子设定，先讨论并独立出验证图，由用户验收后再用于剧情页；未变的已验收设定直接复用。
- 改动作瞬间、姿态或分页等画面方案先讨论；出图遇到问题时的机位、构图与画幅试验按[构图测试规则](prompt-generation.md#构图测试)执行。

## 必要上下文

| 任务 | 读取范围 |
|---|---|
| 故事、seq | 用户来源、当前 synopsis/outline、相关 profile |
| 分页、跨 seq 重组 | 当前及邻接段落摘要、涉及页面正文和必要图片 |
| 角色／场景子设定 | 当前设定、可复用子设定、必要参考图 |
| 文案优化 | 页面内容、说话人、必要角色背景与语料命中上下文 |

机械操作只读保证正确所需的事实，不为每次操作扫描全项目。语料检索指定所属项目，资料归属见[项目事实](../reference/project-files.md)；进入 Prompt 或出图时读[Prompt 与生成规则](prompt-generation.md)。
