# 创作指南

## 用户主导，按当前要求推进

用户把控故事、审美、范围和推进时机。Agent 提供可修改的原型并处理具体操作；完成当前明确的一步后交付，不默认继续下一单元、后期优化或整项目制作。用户明确委托更大范围时，按该范围执行。

当前范围内的普通操作自行完成，不逐页、逐批重复请示。新故事事实、视觉方向变化或扩大范围需要与用户讨论；已确认决定直接沿用。确认留在会话中，不新增项目审批状态。

默认视觉小品优先：故事合理易懂、前后不矛盾即可。同一情节可以通过不同机位、姿态、表情展开，不要求每页推进剧情，不主动增加复杂动机、人物弧线、反转或深意台词。

## 从讨论到原型

1. **完整故事骨架**：先与用户讨论 synopsis、chapter、sequence 和必要角色 profile。形成完整版本并集中说明主要调整，由用户确认后逐单元细化。已有有效骨架不重新追查确认。
2. **单元分页草案**：用户提供单元内容与基础文案，Agent 提议页数、顺序、每页基本画面、基础文案分配和简短机位建议。用户修改确认后再执行；提出草案不等于获准生成。
3. **执行当前范围**：使用已验收的角色子设定，把确认稿落实到页面和 Prompt，并生成首轮图片。委托制作一个单元时默认按整个单元交付；只要求草案、单页或局部修改时完成相应范围即可。
4. **用户精修**：交付图片和主要问题，用户继续调整。文案优化、下一单元、批量扩展和专项实验另按用户要求处理。

这些是常见交接点，不是单向阶段关卡。制作和改图中可以回头讨论骨架或分页；用户确认调整后只更新受影响内容，不重跑整个流程，也不为了迁就模型静默改故事。

## 职责与协作

保留四种专业职责，按任务需要使用，不要求四个常驻实例或额外协调层。单个 Agent 可以依次承担当前任务所需职责；使用对应技能和事实入口。多 Agent 工作应有当前任务的明确需要与授权，职责边界用于避免交叉写入，不建立角色认证。

| 职责 | 技能 | 负责内容 |
|---|---|---|
| 剧情导演 | story-direction | 完整故事骨架、角色 profile，讨论必要的故事调整 |
| 剧情编辑 | story-editing | 分页草案、页面顺序、画面内容、基础文案落实；后期文案优化另行委托 |
| 视觉导演 | visual-production | 出图前的角色与整组视觉方向、镜头建议，指出首轮偏差，不挑选候选 |
| Prompt Agent | prompt-authoring | 角色与页面 Prompt、生成、严重问题检查和有限修正 |

涉及别人的写入范围时说明依据和受影响对象；有多 Agent 分工时直接交接相关责任方。分歧简短交换依据，涉及用户偏好就交用户，不持续内部讨论或增加裁决层。没有多 Agent 时不为文件边界强行派发成员。

交付不需要剧情导演的 story-ready 或视觉导演的内容就绪信号。按用户要求交付草案、原型或局部修改，说明仍有的问题，不把原型宣称为最终成品。探索、可靠性测试、复盘都是专项能力，不作为普通制作的必经环节，也不自动应用到范围外页面。

## 读取必要上下文

设计或调整剧情页前，从 synopsis、所属 chapter 摘要与该章 sequence 摘要理解当前段落，再按 index 阅读当前 sequence 已有 narrative；补读本次涉及的角色配置、Prompt、约定和必要图片。同一轮已读且未变化的内容不反复读取，不默认扫描全项目候选与历史。

明确的机械操作只读取保证该操作正确所需的事实和依赖。涉及故事、人物状态或镜头关系的判断不能仅靠单页或 Agent 消息。上游改变时重新读取受影响事实，再修正当前授权范围内的下游；不自动扩展到所有消费者。

## 页面与文案

画面内容用简短白描表达谁在做什么，沿用 20 字以内的创作规范；不复述角色外观或写设计意图。字数不是保存或生成门槛。允许相邻页内容相近，以机位和表现变化形成节奏。

分页草案只展开既有故事事实，可以安排普通姿态、表情和视线；需要增加原因、结果或关系变化时回到故事讨论。用户基础文案原样分配到页面，不主动润色、补写或改变标点。没有提供的文案不擅补；分配不明时在草案中指出。

文案优化后置，只在用户要求时处理。语料供参考，不要求照抄，不再要求建立出处映射。当前尚存的映射文件与接口不是写作要求，功能移除须由独立代码变更完成；不因本轮文档调整删除项目事实。方法见[文案参考](../../library/writing-policies/copy-from-corpus.md)。

## 角色与 Prompt

内容编辑前用 `page.editor.read`，Prompt 编辑前用 `prompt.read`，完整读取本次涉及的范围；不要求展开全局、角色和场景后的完整输入。同轮未变内容不重复读取。需要理解引用或排查最终输入时再按需查询 `prompt.context`，不把只读展开内容写回页面；详见[Agent 接口](../reference/agent-interfaces.md)。

新增子设定先与用户讨论，单独生成验证图并由用户验收后才能用于页面；不能用 Agent 自评代替。既有已验收且未变的配置复用，不反复验证。实质改变已验收配置时，也先交用户验证受影响部分；LoRA 变更仍需明确同意。

角色配置与验证图只表达必要内容，不追求逐部位精密描述。验证页在配置之外只补展示所需的姿态和镜头；不再写另一套完整外观要求。字段与 override 行为以[项目文件](../reference/project-files.md)和当前接口为准，不能根据旧字段说明补回已被用户精简的内容。

Prompt 只表达目标方向，不增加细节或拆解动作的身体实现过程。动作名足够时只写动作名，关系用简短自然语言；页面动作／关系描述每条最多 20 个英文单词，不拆条绕过，不以确认稿、必要性或细微姿态问题为扩写例外。长度只约束 Agent 编写，不作为保存门槛。

外观和基础场景可合并成段，不套用动作／关系的词数上限，但同样不得擅加细节。同一环境优先引用共享场景，页面只补局部差异，一次性环境可直接写本页。不要堆同义词；查看最终编译结果后再判断完整性与冲突。

Qwen 镜头用简短语言直接写进自由文本；Anima 使用分类词条、逐词权重、负向与机位控件。按当前模型编辑，不把某一模型的字段套到其他模型；详见[模型适配器](../dev/model-adapters.md)。

## 默认出图与交付

插画原型每页生成 **3 张**并全部保留供用户查看，不做候选挑选或自动删除。H3 动态页默认一个视频候选，流程见[动态页](../dev/video-pages.md)，不套用三张图片的重试规则。逐张检查额外人物、严重肢体错位、主体错误等明显问题；普通审美差异、轻微瑕疵不触发自动修正。

同页三张中 **至少两张有严重问题**，可在既定事实内修正一次 Prompt，再生成三张。第二批仍有问题就说明并交用户，最多一次自动修正；不继续补样，不降低目标。配置或服务失败只报告实际问题，不计为审美重试，也不触发无限任务重提。用户明确指定的生成数量或专项试验预算优先。

当前范围内、输入已确认且互不依赖的页面可以并发提交；后续方案依赖本批结果时等待判断。交付当前范围、结果入口、做过的修正和主要问题，不逐候选评分，不继续下一阶段。

## 操作边界

项目事实只能通过现有 read/save 或语义命令修改。沿用 read 返回的目标与依赖指纹；Prompt 使用保存参数加 changes，其他事实按对应契约提交 document。busy 有界退避，指纹冲突重新读取判断。用户原文和材料不擅改，不替用户选择候选或修改文字样式；提交或推送须有用户明确授权。

具体字段、生成与嵌字功能见[项目文件](../reference/project-files.md)、[Prompt 参考](../reference/prompt.md)、[视觉页面](../reference/visual-pages.md)和[操作接口](../reference/agent-interfaces.md)。
