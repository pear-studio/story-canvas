# Prompt 与生成协作

本文维护模型无关的编写和交付规则；操作契约查 `story_canvas` help。日常插画使用 Anima，动态页使用 H3；备用 Qwen 按需读[专用文档](../reference/qwen.md)。

## 表达与修正

- Prompt 优化改善同一已确认画面目标的表达；构图问题按下节测试，其他画面方案调整遵循[创作确认](guide.md#确认边界)。
- 优先复用上游稳定表达，本页只补当前需要。修正先检查最终输入，关闭不应入镜的继承词，再删除重复、矛盾、无关词，重新组织整页，不逐轮叠加补丁。例如第一人称中不应看到的视角角色头发、眼睛，以及妨碍当前构图的场景物体。
- 共享设定按可独立取舍的内容组织词条；人物外观、场景物体、环境、光线等不要混杂在同一描述中，以便按页关闭，不逐细节过度拆分。
- 模型注意力有限，检查整页描述总量，只在少数关键结构或关系使用具体限制；不逐部位、逐步骤指导动作。
- 通常词条组合足够。动作或属性反复迭代仍容易漂移到其他角色时，才用短语锚定某人或两人的相对关系；可结合名字、发型、发色、girl／boy 等当前画面可见特征，不为锚定加入不应入镜的外观。
- 动作／关系描述尽量单条不超过 20 个英文单词；必要说明可稍长，不拆条绕过。它是辅助规范，不是保存或生成门槛。
- 特定动作或专有词含义不明确时，查词典 Wiki 的定义、别名与相近词，考虑替换或少量组合；同义词不机械堆叠，仍控制整页总量。由此获得的新动作灵感按画面方案另行讨论。
- Anima 词条权重优先选网页预设，不自主细分；已有值不自动取整，用户明确指定优先。此偏好不用于 LoRA 权重，预设数值查工具字段帮助。
- 任何 LoRA 新增、删除、替换都须用户明确同意。除下述构图测试外，自动纠错不改变参考图、LoRA 或生成参数。

## 构图测试

- 插画出图遇到问题时，可自行调整机位、构图或画幅并生成对比，再与用户讨论调整及结果；沿用已有生成授权、预算与修正次数。改变剧情、人物或核心动作仍先讨论。
- 可测试镜头方向、俯仰角、第一人称，也可不指定机位，让模型自行组织复杂画面或动作。通常竖图够用；按内容需要的横向、纵向空间考虑横图。这些只是可行思路，逐次按实际结果判断，不盲从。

## 生成与交付

- 数量沿用工具的图片／视频默认值；用户明确的数量、范围和预算优先。只委托文本时不自动出图。
- 插画至少两张有明显结构错误或偏离核心人物、动作、关系目标时，可自动修正 Prompt 后再生成，首轮后最多三轮。轻微瑕疵和审美差异不触发；服务失败先处理环境，不无限重提。
- 视频耗时较长，不自动修正或重试，根据用户反馈调整；连续播放验收，抽帧不能证明全程或循环接缝正确。
- 不推荐、排名或替用户选图，不解释各批次。新候选成功并匹配当前输入后清理旧 Prompt 对应候选，保留成品仍引用的候选；安全顺序查 `candidate.cleanup.preview` help。
- 交付最新结果入口和仍存在的主要问题，用户自行微调、重生成和选图。

按需比较模型或参数时使用 `comparison` 工具；同种子不保证构图一致，多因素同时变化只代表组合差异，少量结果不能证明稳定性。
